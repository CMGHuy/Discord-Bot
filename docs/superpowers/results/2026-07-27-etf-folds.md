# Task E80: ETF baseline strategies fold-run

Universe: **etfs** (`swingbot.core.universe.universe_symbols("etfs")`, 17
symbols: SPY, QQQ, IWM, DIA, XLK, XLF, XLE, XLV, XLI, XLP, XLY, XLU, XLB,
XLRE, XLC, GLD, TLT). Fetched into `data/backtest_cache/` (2018-06-01 ..
2025-12-30) specifically for this task -- these symbols were not previously
cached there (only the 78-ticker watchlist was).

## A prerequisite gap this task exposed (fixed first)

E80's own step 1 instruction (`SCAN_UNIVERSE=etfs python scripts/wf_run.py`,
plus `python scripts/fetch_backtest_data.py --universe etfs`) does not
actually scope a run to ETFs:

- `fetch_backtest_data.py --universe etfs` populates `market_data/`
  (Task E15's incremental cache), which the fold harness's `_frame_for()`
  never reads -- it reads `data/backtest_cache/` only (see that function's
  own docstring on the two-cache split). Running it as written would have
  produced a "successful" fetch that fed nothing.
- `run_backtest_range.py` (the tool that actually computes the
  win_rate/expectancy_r/N acceptance gates from
  `docs/claude/backtest-methodology.md`, and the tool `--emit-registry`
  actually lives on) had **no universe-scoping flag at all** -- hardcoded to
  `sorted(load_watchlist())` in two places.

Fixed as prerequisites (separate commits, both with tests): `backtest_wf.py`
gained a real `tickers=` override threaded from `run_folds()` (it had
already declared the parameter but never used it), exposed on
`wf_run.py` as `--universe NAME`; `run_backtest_range.py` gained the same
`--universe NAME` via a new `_tickers_for_run()` seam.

**Registry safety:** `swingbot/core/registry.py` reads
`swingbot/core/validation_registry.json` **live** to badge real alerts. That
file already has whole-watchlist entries for these exact strategies
(Support/Resistance n=148 VALIDATED, Break & Retest n=148 VALIDATED, from
the 2024-2025 VALIDATION window). The registry's merge key
(`source, strategy, horizon`) has no universe dimension, so merging an
ETF-only run into that file would have **silently overwritten** those
whole-watchlist badges with 17-ticker numbers, corrupting what every
non-ETF alert displays. Confirmed with the user: ETF-scoped runs write to
a **separate** file, `docs/superpowers/results/etf_validation_registry.json`,
never merged into the live one.

## Run 1: fold harness sanity check (`scripts/wf_run.py --universe etfs`, no component overrides)

Per E80 step 1's literal instruction ("baseline strategies only" = no
component overrides, so baseline == component and delta is definitionally
0.0000 -- the `PRE-REGISTERED GATE: FAIL` lines below are that delta gate,
not an acceptance-gate result; they're expected and not meaningful here).
What is meaningful is the raw per-fold baseline `expectancy_r`/N:

```
Support/Resistance
fold         N    baseline   component     delta
2021        20      0.2442      0.2442    0.0000
2022         6      0.1417      0.1417    0.0000
2023        11      0.0319      0.0319    0.0000

Break & Retest
fold         N    baseline   component     delta
2021       128      0.1272      0.1272    0.0000
2022        66     -0.0684     -0.0684    0.0000
2023        68     -0.0634     -0.0634    0.0000
```

Support/Resistance's baseline expectancy was positive in all three fold
years on ETFs alone (though N is thin -- 6 to 20 trades/fold). Break &
Retest was positive in 2021 but negative in both 2022 and 2023 -- an early
signal, confirmed by Run 2 below, that this strategy's watchlist-wide edge
does not carry over to the ETF-only universe.

## Run 2: TRAIN acceptance-gate harness (`scripts/run_backtest_range.py --train --universe etfs`)

TRAIN window 2020-01-01..2023-12-31, pass rule per
`docs/claude/backtest-methodology.md`: `win_rate >= 80, expectancy_r > 0,
N >= 30, scratches+timeouts <= 50%`.

```
Strategy                   N   Win%    ExpR  MaxDD%   Scr    TO  Excl%  PASS
Support/Resistance        36   97.2  +0.142    -1.6    18     2    36%  PASS
Break & Retest           234   74.8  -0.050   -25.7   104     0    31%  FAIL
```

Per the methodology's run-once-validation-budget rule ("a config that fails
train never gets a validation shot"), **Break & Retest does not get a
validation run** on the ETF universe. Support/Resistance passed TRAIN and
is eligible for a future validation-window run, not spent here.

## Comparison against the existing whole-watchlist registry (window mismatch -- not apples-to-apples)

| Strategy | ETF-only (this run, TRAIN 2020-2023) | Existing registry (whole watchlist, VALIDATION 2024-2025) |
|---|---|---|
| Support/Resistance | N=36, WR=97.2, ExpR=+0.142, **PASS** | N=148, WR=87.1, ExpR=+0.326, VALIDATED |
| Break & Retest | N=234, WR=74.8, ExpR=-0.050, **FAIL** | N=148, WR=84.5, ExpR=+0.21, VALIDATED |

The two columns are measured on different windows (TRAIN vs VALIDATION) and
different universes (17 ETFs vs the 78-ticker watchlist), so this is a
directional read, not a like-for-like comparison. Support/Resistance's edge
looks like it generalizes to the ETF-only universe (higher win rate, in
fact, likely because ETFs trend cleaner with fewer whipsaws than individual
names). Break & Retest's watchlist-wide edge does **not** carry over to
ETFs alone -- worth flagging if ETF-specific alerts for this strategy are
ever surfaced separately, though nothing in the live path does that today.

## Honest observations

- Indices/sector ETFs trending cleaner than individual names was the
  stated expectation going in ("indices trend cleaner"); Support/Resistance
  bears that out (WR 97.2% on ETFs vs 80.6% on watchlist TRAIN). Break &
  Retest does not -- its edge appears to depend on individual-stock
  volatility/retest patterns that don't show up the same way in ETFs.
- N is thin on the fold-harness side (as low as 6 trades in one
  Support/Resistance fold year) given only 17 symbols across 3 one-year
  windows; the TRAIN acceptance run (4-year window, N=36) is the more
  reliable of the two numbers for Support/Resistance.
- No registry entries were merged into the live `validation_registry.json`.
  `docs/superpowers/results/etf_validation_registry.json` holds the 2 ETF-
  scoped records (Support/Resistance VALIDATED n=36, Break & Retest WEAK
  n=234) as a separate, non-live record of this run.
