Probe caveats, recorded so the table is not over-read:
- The deployed rail has no `aria-label` on `a.rail-link` (the task's DOM contract); the probe matches the rail by its label text. Analytics and Calendar are not rail entries (Insights / Trades sub-pages), so they are reached by an in-app router navigation (history + popstate, no reload).
- On those in-app navigations "first data" can be read from the previous page's still-visible content (Analytics 0.0 s / 0.1 s, Calendar 0.1 s in the scan pass): treat those first-data figures as unreliable, not as passes.
- A visit's call window starts at the click and runs to the end of the settle, so requests the SPA's shell and the previous page still had in flight (`/dashboard`, `/live`, `/market/tape`, `/watchlist/tickers`) are counted against the visit. The verdict rules were not changed.
- A scan was already running when the run began, so the scan pass ran immediately after warm, while the probe's own passes and the live scanner overlapped. Production was also under the scan's load (`/system/scan` up to 2415 ms).
- Non-GET requests aborted by the probe: 0. One login.
