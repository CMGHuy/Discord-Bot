## Stall windows

--project-directory /opt/swing-bot exec -T db psql -U swingbot -d swingbot
-At -F '|' -v ON_ERROR_STOP=1`. Timestamp expressions used
`to_char(<aggregate>(closed_at) AT TIME ZONE 'UTC',
'YYYY-MM-DD"T"HH24:MI:SS.US"Z"')`.

The plan's original queries returned:

  `w1_last_close_before|2026-08-04T18:55:42.471169Z`
- `min(closed_at)` at or after `2026-08-04 18:55:00+00`:
  `w1_batch_first_close|2026-08-04T18:55:15.072977Z`
- `max(closed_at)` before `2026-08-05 15:34:08+00`:
  `w2_last_close_before|2026-08-05T15:34:07.518002Z`
- `min(closed_at)` at or after `2026-08-05 15:34:00+00`:
  `w2_batch_first_close|2026-08-05T15:34:01.332561Z`

**Finding and correction:** the original last-close cutoffs fall inside the
catch-up batches, selecting closes later than each batch's first close and
producing reversed windows. Those values cannot define a stall. The
controller approved querying the last close before each batch minute instead:

- `max(closed_at)` before `2026-08-04 18:55:00+00`:
  `w1_last_close_before_batch_minute|2026-08-03T16:18:02.873898Z`
- `max(closed_at)` before `2026-08-05 15:34:00+00`:
  `w2_last_close_before_batch_minute|2026-08-05T14:40:57.702845Z`

The per-minute query grouped `closed_at` between `2026-08-03 12:00+00`
and `2026-08-05 20:00+00` by `date_trunc('minute', closed_at)`. Its boundary
lines were:

- `by_minute|2026-08-03T16:18Z|1`
- `by_minute|2026-08-04T18:55Z|25`
- `by_minute|2026-08-05T14:38Z|1`
- `by_minute|2026-08-05T14:40Z|1`
- `by_minute|2026-08-05T15:34Z|7`
- `by_minute|2026-08-05T15:36Z|1`

There were no intervening rows between the first two lines, nor between
14:40 and 15:34 on August 5. The output therefore supports both batch-minute
cutoffs. Window 1's start matches the spec to the second; its first batch
close is 18:55:15, rather than the assumed 18:55:43. Window 2's first batch
close is 15:34:01, rather than the assumed 15:34:08. The JSON uses these
observed values, truncated to the second as required by the task.

Rule note for V200-9: under `opened_at < end` and `closed_at >= start`, the
trade whose close defines a window start is itself inside the window.
