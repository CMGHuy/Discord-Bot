**Goal:** Three Discord-surface changes that leave the measured book untouched. **D1:** a dedicated channel (`DISCORD_CHANNEL_NOTIFY_ID`) that posts factual paper-plan updates (near stop, TP1, TP2, stopped, expired; closed/cancelled for Following followers only) and mentions the users who follow the plan, idempotent with its own retry, with `/notify` per-user settings. **D2:** a persistent plan panel (`DynamicItem` buttons that survive restarts, a fallback for pre-v152 static ids), per-user Watch, a `✅ Following` button, a denormalised `taken_by` on the trade and a `taken` analytics dimension. **D3:** a per-symbol alert cooldown (`ALERT_SYMBOL_COOLDOWN_HOURS`, default 24) on the scheduled scan only, failing open, with a visible held count.

**Architecture:** One DDL revision `v152_001` adds four hybrid tables (`plan_followers`, `plan_notifications`, `notify_prefs`, `alert_posts`), each with its own repository under `swingbot/core/db/repositories/` (custom SQL for composite keys, `ON CONFLICT DO NOTHING` and the attempts counter — `Repository` is single-key). `PlanManager.poll` gains one `events.extend(self._near_stop_event(...))` statement; `notify_plan_events` skips `FOLLOW_ONLY_EVENTS`. A new `swingbot/commands/scanning/follow_notify.py` maps `PlanEvent`s to notify events through two dicts, renders a `PushEmbed` from a copy table, claims `(plan_id, event)` in `plan_notifications`, sends, and sweeps pending rows once per `trade_monitor` tick. `views.py` moves to `discord.ui.DynamicItem` buttons registered in a new `bot.setup_hook`. A new `swingbot/commands/scanning/cooldown.py` owns `alert_posts`; `_send_alerts(apply_cooldown=True)` filters before the cap.

**Tech Stack:** Python 3.11, discord.py 2.7.1 (`DynamicItem` from 2.4), SQLAlchemy + Alembic on Postgres, pytest (no pytest-asyncio: drive coroutines with `asyncio.run`); Angular 21 + Vitest for the one SPA task.

## Global Constraints

- **The book is unchanged.** Nothing here alters which plans are built, filled, stopped or closed. D3 suppresses only the Discord post; the plan and its placeholder trade are already persisted by `scan_run` before `_send_alerts` runs. D2's `taken` splits the existing book.
- **Copy rule (D1).** Every notify message is factual paper-plan wording, no imperatives; the embed footer ends with `Paper plan update, not advice.`; `FORBIDDEN_PHRASES = ("exit now", "move stop", "move your stop", "take profit", "sell now", "buy now", "close your", "you should")` never appears in content, title, description, fields or footer. `Kind.MOVE_STOP` and `Kind.CANCEL` are never used by the notifier. Every message on an ACTIVE or PARTIAL plan states the current `resting_stop(plan)` and the remaining target.
- **Following is intent, not a fill.** User-facing wording says "followed", never "executed"/"taken"/"filled". The SPA caption is verbatim `Paper results, R units, pre-tax. Followed records the plan as followed, not your fill.`; the option label is verbatim `Followed vs paper`.
- **Fail open (D3).** Any error in `cooldown.suppressed` or `cooldown.record` → the alert posts and one WARNING is logged; a cooldown fault never raises into the scan. `StoreWriteHalt` still propagates untouched from `_run_scan_posting_partial` (its re-post never passes `apply_cooldown`).
- **Suppression scope (D3).** `apply_cooldown=True` is passed only by `session_scan`'s `send_then_short` call (`loops.py:199`). Never by: the store-write-halt re-post (`loops.py:114`), the admin-UI triggered scan (`loops.py:454`), `!check` (`commands.py:217`), `commands.py:173`, or the outlook post (`outlook.py:83`, unmentioned by the spec — decided here: **not suppressed**, it is not the scheduled session scan; V152-15 pins it with a test).
- **Every new DB call from a Discord button, the notifier, the cooldown or `/notify` runs through `asyncio.to_thread`.** `close_plan_trade` already runs inside the manager's sync tick thread, so its follower read is a plain sync call there.
- **Never pass the notify channel through `silence()`** (`core/infra/silent_channel.py:69`): mentions must ping. Resolve it with `bot.get_channel(int(config.DISCORD_CHANNEL_NOTIFY_ID))`. Empty key → the notifier sends nothing and claims nothing.
- **Use `ui.push_kwargs(embed)`** for every embed send (`known-traps.md`: a bare `send(embed=)` drops the push line); merge the mention text into its `content`, do not clobber the push line.
- **Complexity.** Every function written or changed ends < 15 (`python -m radon cc -s -n C <files>`; radon is not installed in the briefer's env — `pip install radon` first). Legacy: `PlanManager.poll` (20) gains one statement and **no branch**; `_step_active` (21) is not edited; `notify_plan_events` 12 → 13 (one membership test); `_send_alerts` 9 → 10 (one branch); `close_plan_trade` 7 → 8. ## Decisions fixed by this index

These settle the brief's drift items and the spec's open seams. Part writers and implementers treat them as the contract.

1. **Alembic.** Revision id `v152_001`, file `swingbot/core/db/migrations/versions/v152_001_follow_notify_cooldown.py`, `down_revision = "v144_001"`. The rollback target in the production notes is `alembic downgrade v144_001`.
2. **Repositories are one per table, keyed on the surrogate `id`** (`Repository(table, key="id")`), with their own SQL for composite keys: `pg_insert(...).on_conflict_do_nothing(index_elements=[...])` via `self._tx(conn)`, `rowcount` deciding "inserted or not". The attempts counter lives in `doc` (`doc || jsonb_build_object('attempts', coalesce((doc->>'attempts')::int, 0) + 1)`), not a promoted column — the spec promotes only `plan_id`, `event`, `state`.
3. **`notify_prefs.doc` is flat:** one boolean per notify event name (`near_stop`, `tp1`, `tp2`, `stopped`, `expired`, `closed_other`) set only when the user toggled it, plus `watch_mode` (`"mention"` | `"silent"`). A missing key means "use the default". Writes merge with JSONB `||` in an upsert (`on_conflict_do_update(set_={"doc": table.c.doc.op("||")(excluded.doc)})`), no read-modify-write.
4. **`alert_posts.at` is `TIMESTAMP WITH TIME ZONE`;** `direction`, `horizon_key`, `plan_id` live in `doc`. Window lookup filters `outcome = 'posted'`, `ticker`, `at >= since`, and the two doc keys. Only rows written by the scheduled path exist: `cooldown.record` is called **only when `apply_cooldown=True`**, so a `!check` or admin-UI post never starts a window (the spec says the rule is "on the scheduled path only").
5. **Persistent panel.** `PlanActionView(plan_id: str, author_id: int | None)` keeps its constructor signature (the `timeout` keyword is removed; the view is always `timeout=None`), so `alerts.py:99`, `alerts.py:211` and `stats.py:~121` need **no edit**. The buttons are `DynamicItem[discord.ui.Button]` subclasses, one per action, template `plan:<action>:(?P<plan_id>[0-9a-f-]{36})(?::(?P<author>\d{17,20}))?`, actions `chart`, `breakdown`, `watch`, `follow`, `dismiss`. The author lock is each item's `interaction_check`, reading the author parsed from the `custom_id`.
6. **Registration hook.** `swingbot/bot_core.py` gains `@bot.event async def setup_hook() -> None` that calls `swingbot.commands.views.register_persistent_views(bot)` (lazy import inside the hook — `views.py` imports the plan store). `register_persistent_views(bot)` calls `bot.add_dynamic_items(*PLAN_BUTTONS)` and `bot.add_view(LegacyPlanPanel())`. There is no existing `setup_hook` (`git grep setup_hook` is empty); `on_ready` keeps the tree sync and the SIGHUP handler.
7. **Legacy fallback.** `LegacyPlanPanel(discord.ui.View)`, `timeout=None`, four buttons with the static ids `plan:chart`, `plan:breakdown`, `plan:watch`, `plan:dismiss`. Chart/Breakdown/Watch reply ephemerally with `LEGACY_REPLY = "This alert predates v152 — use the plan page or \`!plans\`."`; Dismiss does `interaction.response.edit_message(view=None)`.
8. **Following writes the trade copy as a set, not an append:** after toggling, the button reads `followers_repo().user_ids(plan_id, ("taken",))` and calls `TradeLog().mark_taken(plan_id, user_ids)`, which patches `taken_by` (sorted list) onto the plan's open trade by `trade_id` with `trades_repo().patch` under `_LOCK`. `close_plan_trade` re-stamps `t["taken_by"]` from the same table read just before its upsert; a failed read keeps the trade's existing value and logs a WARNING (a close is never blocked).
9. **Mention policy is a pure table** in `follow_notify.py`: Following (`taken`) followers default ON for all six events; Watch-only followers default ON for `tp1`, `tp2`, `stopped`, OFF for `near_stop`, `expired`, and never mentioned for `closed_other`; `watch_mode="silent"` drops every Watch-only mention; an explicit per-event toggle overrides the default for either kind. A user with both rows counts as Following.
10. **`near_stop` lives in `FOLLOW_ONLY_EVENTS = frozenset({"near_stop"})`, defined in `plan_manager.py` beside `STOP_EVENTS`**; `lifecycle_embeds.notify_plan_events` imports it and `continue`s on membership before its history branch.
11. **Claims dedupe.** `follow_notify` keeps a module cache `_CLAIMED: set[tuple[str, str]] | None`, seeded once from `notifications_repo().claimed_keys()` (every row, any state); an event whose key is cached is dropped before any DB call, so a near-stop firing every in-band tick costs one set lookup. A `claim()` that returns `False` adds the key too.
12. **Retry.** `retry_pending_notifications(bot, now=None)` re-sends rows with `state='pending'` and `updated_at` older than 60 s, from the stored `doc` (`{"transition", "detail", "attempts"}`) and the plan's current store state; after the 5th failed attempt the row is `failed` and a WARNING is logged. It runs once per `trade_monitor` tick **outside** the `if plan_events:` guard.
13. **Held alerts.** `_send_alerts(..., *, apply_cooldown: bool = False) -> list` returns the plans it held (empty list otherwise; existing callers ignore it). `post_short_universe` gains `held: list | None = None` and extends it; `send_then_short(..., apply_cooldown=False) -> list` returns the union. `session_scan` posts `cooldown.held_note(held)` through a guarded `loops._post_cooldown_note(held)` (`channel.send(content=..., silent=True)` on `_ops_channel()` in a `try`, WARNING on failure) — `notices.send_guarded` takes an embed, so it is not reused.
14. **Digest line.** `_post_daily_digest` appends ` · N alert(s) held by the symbol cooldown today` to its content line when `N = cooldown.held_today()` (Berlin session date, via `to_thread`) is > 0; `digest_payload` is unchanged.
15. **`taken` dimension extractor:** `"followed" if t.get("taken_by") else "paper"`. `tests/analytics/test_aggregate.py::test_all_ten_dimensions_present` becomes an eleven-dimension assertion (renamed `test_all_eleven_dimensions_present`); `analytics.store.spec.ts:739-743`'s exact list gains `taken`.
