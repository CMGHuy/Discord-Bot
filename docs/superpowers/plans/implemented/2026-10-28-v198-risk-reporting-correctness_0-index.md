# Risk reporting correctness implementation plan

> For agentic workers: use subagent-driven-development or executing-plans, one task at a time with review. This is documentation, not execution authorization.

**Bump:** ui patch, bot patch
**Edge:** none (integrity)
**Spec:** [Approved risk spec](../specs/2026-10-28-v198-risk-reporting-correctness.md)

**Goal:** Correct three demonstrated reporting failures: unavailable sources appearing safe, short positions contributing long returns, and drawdown omitting initial losses or walking the wrong chronology. Preserve useful independent data when one source fails. Add explicit coverage and unknown states throughout the API, Risk page, shell killswitch display and Discord portfolio command. Keep scan gates, sizing, stops, account accounting and entry/exit behavior unchanged. Synthetic numerical cases and injected dependency failures establish success; this plan makes no live-book performance claim.

**Architecture:** First decompose the high-complexity portfolio collector without behavioral changes. Then keep availability beside each independently collected value and expose a nullable read contract to all reporting consumers. A small admin Risk read-model module owns signed gross-normalized weights and chronological closed-record selection. The pure drawdown helper gains its missing zero baseline; general r_multiples ordering remains unchanged.

**Tech stack:** Existing Python/pandas, Flask, Angular/Vitest and shared market-data/FX interfaces; no new paid service, database schema, external data source or persisted reporting store.

### Availability

V198-2 introduces `availability`: each entry is `{state: 'ok'|'partial'|'unavailable', checked_at: UTC ISO string, reason: string|null}`. Required collector/API keys are `positions`, `heat`, `sector_heat`, `clusters`, `throttle`, `killswitch`. V198-4b adds API key `distribution_metrics`; V198-5b adds `drawdown_r` and `drawdown_amount`. V198-3 declares those three later keys optional until their producer tasks land; absence never asserts successful measurement. The type is `RiskAvailability`; each entry has type `DomainAvailability` in `frontend/src/app/api/models.ts`.

Collector `collect_portfolio_state() -> dict` retains existing names and additionally returns `open_trades: list[dict]|None`, `balance: float|None` and `availability`. API positions use that same snapshot, not a second independent read: V198-2b changes `_positions(open_trades: list[dict]|None, balance: float|None) -> list[dict]|None`. Unknown rows return None; known identities survive unknown heat, with per-position `risk_pct=None`. Known-empty rows return []. Collector `open_heat`, `throttle_mult` and `paused` are nullable; unavailable collector sector/clusters are None, not measured empty. API `heat.open_pct/utilisation_pct`, `throttle.multiplier/paused`, `killswitch.on`, `positions`, `sector_heat` and `clusters` are nullable as appropriate. Sector `unmapped_count` keeps its v194 meaning when positions are known; availability takes precedence when they are not. A bad balance invalidates heat/sector percentages, never position identities. A partial map retains known-sector rows and counts unmapped positions.

Fresh killswitch reads determine current state on every Risk response and on the dedicated endpoint, even after a successful cached read. `_kill_block(state: dict) -> dict` must preserve nullable `on`; it must not coerce None to False. Killswitch wire shape adds `availability: DomainAvailability` and optional `last_known: {on: bool, reason: str|null, at: str|null, checked_at: UTC ISO string}` to existing `on/reason/at`. Its nested availability also appears as top-level `availability.killswitch` in the Risk resource. `KillswitchResult` remains `{killswitch: Killswitch}` so the shell and mutation share that object. Last-known state is process-local observation only, timestamped when observed, visibly stale and never substituted into current fields. `_invalidate_cache()` clears test-visible cached observations too. The POST request remains a strict boolean; a failed read never prevents an explicit authenticated command attempt and never generates an off mutation. After readback failure, report current unknown rather than claiming the requested state was observed.

`RiskStore` exposes nullable current state and availability to templates. On whole-request/network failure it marks retained figures stale, and shell killswitch current state becomes unknown; last-known state is separately labelled. For an unknown current killswitch, actions choose explicit `true` or `false`; never negate a nullable signal. Discord `portfolio_report(state)` prints unavailable for each failed domain and partial for incomplete coverage, preserves successful domains, and preserves prefix/slash parity through the existing fixture.

Reason codes are sanitized machine strings, never exception text. Minimum stable codes used across parts: `positions_unavailable`, `account_unavailable`, `invalid_balance`, `heat_unavailable`, `sector_map_unavailable`, `sector_mapping_incomplete`, `sector_heat_unavailable`, `clusters_unavailable`, `clusters_incomplete`, `throttle_unavailable`, `killswitch_unavailable`. Successful empty reads are ok; missing bars for a nonempty cluster population must not become known no-clusters. Cache value/status together with the original checked_at; do not refresh an observation timestamp merely because its cached value was served.

### Signed weights

`signed_weights(open_trades: list[dict], *, on: date, account: str|None=None) -> tuple[dict[str,float], str|None]` is created in `swingbot/admin/api_v1/risk_read_model.py` by V198-4. It consumes the v194 fx.account_currency_code/quote_currency_code/fx_rate seam. reason None means complete coverage; a reason means no distributional result is defensible. Validate finite positive entry/shares, recognized bullish/bearish direction and positive finite FX. Aggregate signed per-ticker notionals, divide by gross before netting. Keep net-zero tickers with zero weights so bar coverage remains explicit, rather than dropping positions. Empty input returns ({}, None).

Do not round weights. If any necessary lookup/record is invalid, return ({}, reason) rather than a partial normalized portfolio. Market-dependent figures become unavailable while trade-derived performance survives. Stable weight failure codes are `invalid_position`, `invalid_direction`, `missing_quote_currency`, `missing_fx`, `invalid_fx`; the API uses `positions_unavailable` for failed reads and `market_data_unavailable`/`incomplete_bars` for market coverage. The actual bar-reader uses the existing shared daily path. Label weight basis as entry notional valued in account currency on the valuation date; label returns as quote returns without historical FX effects.

V198-4b changes `_risk_metrics_and_correlation() -> tuple[dict, dict, dict]`: metrics, underlying-asset correlation, and a domain-availability mapping. `get_risk()` merges the third mapping into the response availability without mutating cached dictionaries. V198-5b extends that mapping with drawdown statuses. V198-3 prepares the static visible basis labels: “Quote returns; entry notionals valued in account currency; historical FX returns excluded” and “Underlying-asset correlation”; use the configured benchmark field for its label. No new currency conversion policy is introduced.

### Chronological records and drawdown

`chronological_records(closed: list[dict], *, outcome: Callable[[dict], float|None]|None=None) -> tuple[list[dict], dict[str,int]]` is created by V198-5 in the read-model module. With `outcome=None`, select by date only, for money conversion after invalid-date filtering; otherwise the callable computes the finite outcome for each record and its exceptions count as invalid outcomes. Parse closed_at into aware UTC (naive timestamps follow the repository's stored UTC convention); reject missing/unparseable timestamps. When an outcome callable is supplied, then validate the relevant finite outcome. Count date failure before outcome failure. Sort valid records by (closed_at UTC, string trade ID). Return counts with `excluded_count`, `invalid_date_count` and `invalid_outcome_count`; excluded_count equals the two reasons' sum. Add these fields to `metrics.max_drawdown_r` and `metrics.sharpe_r`, which share the selected R population. Partial usable population means partial availability; all invalid means unavailable, while a truly empty successful read is ok with null values. Stable reason codes are `invalid_closed_records`, `closed_trades_unavailable` and `money_conversion_unavailable`. Money drawdown keeps `fx_missing_count`, adds `invalid_date_count`, and counts valid finite converted amounts in `n`. Date-invalid records are excluded before conversion, never double-counted as missing FX. An unsettled amount remains omitted without falsely counting missing FX. Nonfinite converted amounts make money drawdown unavailable; do not silently drop them. V198-3 declares the later exclusion fields optional and renders them when present; V198-5b supplies them.

For the pure max_drawdown_r helper, empty remains None, finite outcomes start with cumulative zero and running peak zero. Nonfinite values yield None at the reporting boundary; never NaN JSON. Audit analytics/report callers before changing the shared helper and preserve their ordered-population contracts; a backtest-linked behavior change requires backtest-gate. Do not globally change r_multiples ordering.
