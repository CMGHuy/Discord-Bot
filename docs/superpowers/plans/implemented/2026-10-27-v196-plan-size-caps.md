## Goal

Plans have become the most expensive thing this repo writes. v195 is 1146 KB over
37 tasks, with a median task of 27 KB, against about 11 KB per task for v186 and
v187. The v193 attempt to steer writers with more tooling was reverted because
every new step re-read the context. The spec's lesson is that a limit a script
checks in one pass costs less than a process that tries to guide the writer.

Once this ships, `scripts/dev/plan_lint.py` fails any plan numbered above v196
that has a task over 20 KB (UTF-8 bytes, measured from its `### Task` line to the
next task, `# ` or `## ` heading, or the end of its file) or more than 20 tasks.
`plan-writer` aims each task at 14 KB or less. When a task goes over the cap, the
writer splits it into `<id>` and `<id>b` and reports `SPLIT:`. When an index
ledger would go past 20 rows, the writer returns `SCOPE` before writing anything
further, and the controller splits the spec in two.

The size check runs inside `scan_file`'s existing line loop through two small
helpers that share a per-file state dict, so lint still makes one pass with no
second read. The task-count check runs once in `lint()`. A version gate,
`CAPS_FROM = 196`, keeps every existing plan (v195 included) out of reach, and a
regression test pins that gate on the committed v195 files.

Nothing a task contains changes: full test and implementation code stays, and
compression stays forbidden. No script, flag, agent phase or briefer step is
added. Success is measured by the sizes of the next two plans, recorded at their
close-out: at most 20 tasks, each 20 KB or less.

**Architecture:** Two constants (`MAX_TASK_BYTES`, `MAX_TASKS`), a version gate (`CAPS_FROM`) and four small functions in `plan_lint.py`. Then doc edits to `plan-writer.md`, `document-conventions.md`, `skills-tools.md` and `CLAUDE.md`, each shipped with its Codex mirror (`AGENTS.md`, plus `.codex/agents/plan-writer.toml` regenerated by `sync_codex.py`).

**Tech Stack:** Python 3.11 stdlib (`re`, `pathlib`), pytest via `scripts/dev/testrun.py`.

not end the span. Plans paste test files and shell blocks that often start with a

the rest of the task would go uncounted and the cap would let it through. The
`### Task` boundary keeps its existing meaning (the same `TASK_RE` that
`record_task` uses) and also resets the fence state, so an unclosed fence cannot
leak into the next task.

def new_task_state(on: bool) -> dict:
    """Per-file state for the task byte budget; `on` is False below CAPS_FROM."""
    return {"on": on, "task": None, "bytes": 0, "fence": None}


def update_fence(line: str, state: dict) -> bool:
    """Track ``` / ~~~ code fences; True while `line` opens, sits in or closes one."""
    m = FENCE_RE.match(line)
    if not m:
        return state["fence"] is not None
    mark, rest = m.group(1), m.group(2).strip()
    if state["fence"] is None:
        state["fence"] = mark
    elif mark[0] == state["fence"][0] and len(mark) >= len(state["fence"]) and not rest:
        state["fence"] = None
    return True


def close_task(name: str, state: dict) -> list[str]:
    """Close the open task span; report it when it is over MAX_TASK_BYTES."""
    task, size = state["task"], state["bytes"]
    state["task"], state["bytes"], state["fence"] = None, 0, None
    if task and size > MAX_TASK_BYTES:
        return [f"{name}: Task {task} is {size / 1000:.1f} KB "
                f"(cap {MAX_TASK_BYTES // 1000} KB) -- split into two tasks, never compress"]
    return []


def track_task_bytes(name: str, line: str, state: dict) -> list[str]:
    """Add one line to the open task; a task, `# ` or `## ` heading closes it first."""
    if not state["on"]:
        return []
    in_fence = update_fence(line, state)
    m = TASK_RE.match(line)
    problems = []
    if m or (not in_fence and line.startswith(("# ", "## "))):
        problems = close_task(name, state)
    if m:
        state["task"] = m.group(1)
    if state["task"]:
        state["bytes"] += len(line.encode("utf-8")) + 1
    return problems
```
