**Goal:** Two integrity gaps in `core/backtesting/registry.py` and the script
that generates its JSON.

**Gap 1 — badges have no time semantics.** `validation_registry.json` rows carry
`run_date` and `Badge` already surfaces it, but nothing anywhere derives
staleness from it. `docs/claude/backtest-methodology.md` has to carry a
footnote saying Fibonacci / RSI / Support-Resistance keep a pre-v31 `VALIDATED`
badge "that now describes deleted arithmetic" — a documentation workaround for
something the data model could state itself. Every consumer
(`plan_engine.py:983`, `admin/queries.py:204`, `insights.py:114`,
`snapshots.py:109`) reads the badge as if it were current.

**Gap 2 — an unhealthy run can still emit a row.** The registry is generated by
`run_backtest_range.py --emit-registry`. A run that produced zero trades, or a
NaN-bearing equity path, should produce **no row at all** rather than a row that
looks like evidence.

**Where both come from.** HKUDS/Vibe-Trading. Their evidence rows decay
`fresh` → `aging` at 90 days → `stale` at 180 days, computed at read time from
the window's own end date and never persisted; stale rows are excluded from
default recommendations. Their `backtest-diagnose` hard-gate checklist is
simultaneously the evidence ingestion gate: a run failing any gate produces "no
evidence rows — never partial rows" and is skipped with a stable
machine-readable token (`hard-gate:zero-trades`, `hard-gate:equity-nan`, …).

**Architecture:** a derived (never persisted) field on `Badge`, a pure
threshold function beside it, refusal tokens in the emit path, and display-only
changes at every badge render site.

**Tech Stack:** stdlib. No new dependency.

## Global Constraints

- **Decay is DERIVED AT READ TIME, never persisted.** Writing a `decay` key into
  `validation_registry.json` would make it wrong the day after it is written,
  and the file's own docstring forbids hand-edits anyway ("hand-edits are
  forbidden except the initial round-1 seed").
- **Decay does NOT gate anything in this plan.** No plan is refused, no alert is
  suppressed, no badge is downgraded because it is stale. Excluding stale
  evidence would change which plans get built — a trading-behaviour change that
  needs its own pre-registered hypothesis and its own shot. This plan makes
  staleness *visible*; acting on it is a successor spec.
- **`run_date` may be missing or malformed.** Rows predate the field and the
  default `Badge` (`registry.py:71`) has `run_date=""`. Unknown age must render
  as `"unknown"`, never as `fresh` — fail-closed on the side of doubt, the
  boundary convention Vibe-Trading states explicitly.
- **Boundaries belong to the stricter side.** `age >= 180` ⇒ stale;
  elif `age >= 90` ⇒ aging; else fresh.
- **A refused run emits no row, never a partial one.** Half a row is worse than
  none: it is indistinguishable from evidence downstream.
- **`_CACHE` is module-global** (`registry.py:13`). Any test that loads a
  fixture registry must call `reload_registry()` in teardown or it poisons every
  later test in the session.
- Verify with `python scripts/dev/testrun.py file <test file>`; `test-runner`
  subagent for the full suite. Green means `0 failed` **and** `0 xfailed`.

```python
"""Read-time decay verdicts derived from a registry row's run_date."""
from __future__ import annotations

import datetime as dt

import pytest

from swingbot.core.backtesting import registry

TODAY = dt.date(2026, 8, 22)


@pytest.mark.parametrize("run_date,expected", [
    ("2026-08-01", "fresh"),      # 21 days
    ("2026-05-25", "fresh"),      # 89 days
    ("2026-05-24", "aging"),      # 90 days -- boundary belongs to the stricter side
    ("2026-03-01", "aging"),      # 174 days
    ("2026-02-23", "stale"),      # 180 days -- boundary belongs to the stricter side
    ("2025-01-01", "stale"),
])
def test_decay_bands_and_boundaries(run_date, expected):
    assert registry.decay_for(run_date, today=TODAY) == expected


@pytest.mark.parametrize("bad", ["", None, "not-a-date", "2026-13-45"])
def test_unusable_run_date_is_unknown_never_fresh(bad):
    assert registry.decay_for(bad, today=TODAY) == "unknown"


def test_future_run_date_is_fresh_not_negative_nonsense():
    assert registry.decay_for("2026-12-01", today=TODAY) == "fresh"


def test_badge_carries_decay(tmp_path):
    fixture = tmp_path / "reg.json"
    fixture.write_text(
        '[{"source":"confluence","strategy":"ALL","horizon":"2m","status":"WEAK",'
        '"n":402,"win_rate":48.8,"expectancy_r":-0.226,'
        '"window":"2024-01-01..2025-12-31","run_date":"2020-01-01"}]',
        encoding="utf-8")
    try:
        registry.load_registry(fixture)
        badge = registry.get_badge("confluence", "ALL", "2m")
        assert badge.decay == "stale"
    finally:
        registry.reload_registry()   # _CACHE is module-global; never leak a fixture


def test_default_badge_decay_is_unknown():
    # The n=0 fallback at registry.py:71 has no run_date to reason from.
    assert registry.Badge(status="WEAK", n=0, win_rate=0.0, expectancy_r=0.0).decay == "unknown"


def test_decay_is_not_persisted(tmp_path):
    # Guard against a future "optimisation" that writes the verdict into the JSON.
    import json
    from pathlib import Path
    raw = json.loads(Path(registry._PATH).read_text(encoding="utf-8"))
    assert all("decay" not in row for row in raw), "decay must be derived, never stored"
```

**Interfaces:**
- Produces: `REFUSAL_TOKENS: tuple[str, ...]`,
  `registry_refusal(result: dict) -> str | None` — the token, or `None` when the
  run is healthy enough to emit.

**The gates**, adapted from Vibe-Trading's checklist to what this harness
actually produces:

| Token | Condition |
|---|---|
| `hard-gate:zero-trades` | `n == 0` — a signal bug, not a result |
| `hard-gate:below-min-n` | `n` under the methodology's floor for the window |
| `hard-gate:nonfinite-metric` | `win_rate` or `expectancy_r` is NaN/inf |
| `hard-gate:missing-window` | no `window` or no `run_date` to date the evidence |

**Read the emit path before writing anything.** `registry.py`'s docstring names
`run_backtest_range.py --emit-registry` as the generator; confirm the shape it
writes and whether `tests/test_emit_registry.py` already asserts a schema. This
task extends that path — it does not replace it.
