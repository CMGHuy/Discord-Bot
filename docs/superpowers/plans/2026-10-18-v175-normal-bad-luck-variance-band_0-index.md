**Goal:**

Every alert already tells the trader how good its setup has been (N, win rate, ExpR, cohort lines). Nothing tells the trader how long or how deep a losing run this book's own past trades produce by chance. A normal bad patch can then be read as proof the system is broken, and a broken system can be excused as "just variance". Douglas's point in *Trading in the Zone* is that both readings fail the trader; the book has never shown which one the current run supports.

Once this ships, the closed book is turned into a series of NYSE close days (each day's R summed, so five stop-outs on one gap day are one loss day). A week-block bootstrap over that series gives the range of losing-day runs and drawdowns over the next 20 and 50 close days, with its own uncertainty ("p95 ≈ 7 (6–8)"). The current run and the drawdown over the last 50 close days are placed against the 50-day band as `normal`, `rough` or `outside`, always beside the book's ExpR with N and window, plus a caveat when that ExpR is not positive. `GET /api/v1/analytics/variance-band` serves the band, a non-interactive "Normal bad luck" panel shows it on Analytics → Overview, and the scan posts one short book-status message in the alerts channel only when the worse zone rises into `rough` or `outside`.

It leaves alone every signal, gate, stop, size, badge, plan embed, the throttle and kill switch, `metrics.streaks`, and the Dashboard. It covers closed trades only (no unrealised P&L) and the whole book only (no per-strategy band; the Analytics scope bar does not apply). The copy describes and never instructs, and never uses the word "edge".

Success is measured by integrity, not lift: the band reproduces exactly from its fixed seed; the calibration test measures the per-look `outside` rate on synthetic i.i.d. and week-correlated books and records it (the caption's "will sometimes appear by chance" rests on it); the message fires only on a zone rise; every existing plan-embed test passes unchanged; and the panel reads correctly at 390, 768 and 1280 px.

**Architecture:** The pure module `swingbot/core/analytics/variance_band.py` holds the whole computation: close-day netting in America/New_York, the current-state statistics, a vectorised week-block path sampler (reusing `stats.iso_week_key`, `stats.WEEK_BOOTSTRAP_SEED` and the `np.random.default_rng` pattern), and the `variance_band(closed) -> Band` assembly (era pool, composition, zones, ExpR with its week-cluster interval, dollars). The admin route `analytics_variance_band` in `swingbot/admin/api_v1/analytics.py` loads the closed book through a seam and returns the band. The bot side adds `Family.BOOK`/`Kind.BOOK_STATUS` to the presentation registry and a never-raising `book_status.post_book_status(channel)` helper, called once per scan tick from `loops._session_scan_tick` with no added branch; the last posted zone is a string in `scheduled_repo()`. The SPA gets a store slice on `AnalyticsStore`, a pure copy/model file and a standalone `sb-variance-band-panel` mounted in `overview.ts`.

**Tech Stack:** Python 3.11, numpy, Flask blueprint `api_v1`, discord.py embeds through the v110 presentation registry, Angular (signals, `@ngrx/signals` store, zoneless), Vitest via `ng test`, Playwright for the three-width check.

## Global Constraints

- **Pure core.** `swingbot/core/analytics/variance_band.py` does no I/O: no store, no `TradeLog`, no network, no file reads, no `config` reads. Input is a list of closed trade dicts (`status in ("win", "loss", "closed")`, as returned by `scope.closed_only`); `scope.select` is never applied (whole book, every ledger: both loaders call `TradeLog().get_trades(status=None, limit=None, ledger=None)`).
- **Frozen constants** (module level in `variance_band.py`; changing one is a new spec): `MIN_DAYS = 100`, `MIN_WEEKS = 20`, `HORIZONS = (20, 50)`, `WINDOW = 50` (the current-drawdown window, `== HORIZONS[-1]`), `PATHS = 10_000`, `SEED = stats.WEEK_BOOTSTRAP_SEED`, `SCRATCH_R = 0.05`, `ROUGH_PCT = 80`, `OUTSIDE_PCT = 95`, `OUTER_RESAMPLES = 200`, `OUTER_PATHS = 1_000` (inner paths per outer resample; a plan choice the spec leaves open), `CI_PCT = (10, 90)`, `EXPR_RESAMPLES = 10_000`, `EXPR_CI_PCT = (2.5, 97.5)`, `ZONES = ("normal", "rough", "outside")`, `CAVEAT = "This book's past results are not positive. A run within their range is still a losing run."`.
- **R and dates.** A trade's R is `metrics.r_multiple(trade)`; a trade with `None` R or no `closed_at` is skipped everywhere. `et_close_date(closed_at: str) -> date` = `datetime.fromisoformat(closed_at).astimezone(session.US_MARKET_TZ).date()` (a naive string is read as UTC first). It deliberately differs from `pnl_calendar.day_of`'s UTC slice: an after-hours close belongs to its NYSE session. The ISO week of a close day is `stats.iso_week_key(day.isoformat())`.
- **Close days.** `CloseDay(day: date, r: float, kind: str)` (frozen dataclass); `r` = the sum of that date's trade R, rounded to 4 dp; `kind` = `"loss"` if `r < -SCRATCH_R`, `"win"` if `r > SCRATCH_R`, else `"scratch"`. `close_days(trades) -> list[CloseDay]` returns them in date order.
- **Losing run** (bootstrap and current state, one rule): consecutive loss days; a scratch day neither extends nor breaks it; a win day ends it. **Drawdown:** running peak of cumulative close-day R (starting from a 0 baseline) minus the cumulative R, in R. In a path the statistic is the maximum drawdown; for the current state it is peak-to-now inside the last `WINDOW` close days.
- **Path sampler.** Weeks are the ISO weeks of the close dates, kept as blocks with their days in date order. Each path concatenates whole weeks drawn with replacement until it holds `h` close days; the last week is truncated. `rng = np.random.default_rng(seed)` once per `horizon_band` call; the main `paths` draw comes first, then the `outer` resamples (each resamples the week set with replacement, then draws `outer_paths` inner paths). Run quantiles use `np.percentile(..., method="higher")` cast to `int`; drawdown quantiles use the default linear method, rounded to 2 dp. `p95_lo`/`p95_hi` are the `CI_PCT` percentiles of the outer p95s (same rounding rules).
- **Zones** against the 50-day band: `zone_of(value, p80, p95)` → `"normal"` if `value <= p80`, `"rough"` if `p80 < value <= p95`, `"outside"` if `value > p95`. With `p80 == p95` the `rough` zone is empty. The overall `zone` is the worse of `run_zone` and `drawdown_zone` (order of `ZONES`).
- **Era pool.** A trade with a truthy `plan_id` is `v2`, else `legacy`. The pool is the v2 trades when they alone reach `MIN_DAYS` close days and `MIN_WEEKS` weeks, else the whole closed book (`pool = "v2" | "all"`). `insufficient` is decided on the whole closed book. Composition is always over the whole closed book: close days per era (distinct ET close dates of that era's trades) and trades per `horizon_key` (`None` counted as `"unknown"`).
- **ExpR beside the band**, over the pool, re-derived on every call: `value = metrics.expectancy_r(pool)` rounded to 3 dp, `n = len(metrics.r_multiples(pool))`, `start`/`end` = first and last ET close date (ISO) of the pool's close days; `ci` = `EXPR_CI_PCT` percentiles of `stats.week_cluster_bootstrap(items, (), mean-R statistic, n_resamples=EXPR_RESAMPLES, seed=stats.WEEK_BOOTSTRAP_SEED)`, each item `_RItem(entry_date=<ET close date ISO>, r=<R>)` (weeks of the close date), rounded to 3 dp, `None` when the bootstrap returns no draws. `not_positive = value is None or value <= 0 or (ci is not None and ci[0] <= 0 <= ci[1])`.
- **Dollars.** Per-trade dollar risk = `float(shares) * abs(entry - stop_loss)` for pool trades with truthy `shares`, both prices present and a risk `> 0`; `median_risk` = their median rounded to 2 dp; `drawdown_usd = round(current.drawdown * median_risk, 2)`. If no pool trade qualifies, the `dollars` key is **omitted** from the band (never `null`, never "—").
- **`Band` shape** (`Band = dict[str, Any]`, JSON-ready). Insufficient: exactly `{"status": "insufficient", "scope": "whole_book", "days": int, "weeks": int}`. Full: keys exactly `status` (`"ok"`), `scope` (`"whole_book"`), `asof` (ISO date of the pool's last close day), `days`, `weeks` (of the pool), `pool`, `composition` (`{"days_by_era": {"v2": int, "legacy": int}, "trades_by_horizon": {str: int}}`), `horizons` (list, one per `HORIZONS` entry in order: `{"horizon": int, "weeks_span": float, "run": {"p80": int, "p95": int, "p95_lo": int, "p95_hi": int}, "drawdown": {"p80": float, "p95": float, "p95_lo": float, "p95_hi": float}}`, with `weeks_span = round(h * weeks / days, 1)`), `current` (`{"run": int, "run_age_days": int | None, "drawdown": float, "drawdown_age_days": int | None, "run_zone": str, "drawdown_zone": str, "zone": str}`; ages are inclusive calendar days from the run's first loss day / the window peak's day to `asof`, `None` when the run is 0 / the drawdown is 0), `expr` (`{"value", "n", "start", "end", "ci", "not_positive"}`), and `dollars` (`{"median_risk": float, "drawdown_usd": float}`) only when available.
- **API.** `GET /api/v1/analytics/variance-band`, `@require_auth`, computed on request (no snapshot), body = the `Band`. Any query parameter → `ApiError("invalid", "unknown parameter '<name>'; allowed: []", 400)`. Seam `_closed_book() -> list[dict]` in `analytics.py` (`closed_only(_all_trades(TradeLog()))`), monkeypatched in tests.
- **Book-status message.** `Family.BOOK = FamilySpec("📉", "BOOK", BOOK_INDIGO)` with `BOOK_INDIGO = 0x6366F1`, and `Kind.BOOK_STATUS = KindSpec(Family.BOOK, "BOOK STATUS")` (no outcome mark, no disclaimer). The embed is `notices.system_embed(Kind.BOOK_STATUS, description=<line>)`; the title (`📉 BOOK STATUS`) carries the badge, so the description is the spec's line **without** its leading `📉 `:
  - rough: `Book: {k} losing days in a row / {dd}R{usd} down over 50 close days, deeper than 80% of simulated runs, within 95%. Closed trades only.`
  - outside: `Book: {k} losing days in a row / {dd}R{usd} down over 50 close days, beyond 95% of simulated runs. Closed trades only.`
