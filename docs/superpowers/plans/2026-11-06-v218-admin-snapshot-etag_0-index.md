## Goal

The admin is one gunicorn worker (`deploy/gunicorn.conf.py`: `workers = 1`,
16 threads), and v205 Layer 1 already made each request read the trade and
plan tables once instead of many times. Every request still reads them
once, though, and on production a `/trades` load still takes about 9 s
median and 11 s p90 during a scan (v206 Results, "Plan 2 after"). The browser
re-asks for identical bodies, and the server rebuilds them from scratch
each time. The idle Dashboard tab also sends 16.5 requests a minute against
a target of under 10. The biggest single source is `/market/updates`, re-read on
every `market` event with no throttle.

Once this plan ships, the admin keeps a per-process snapshot of the raw
trade, plan and journal-note records between requests (v205 L2-a). An
always-on database listener started with the admin invalidates it.
`trades` and `journal` NOTIFYs bump a generation counter. Each request
also compares the stores' `version()` tuples, which catches the case where
a POST is followed by a GET before the NOTIFY arrives (L2-b). Records leave the snapshot as
shallow copies and are frozen deeply under test (L2-c), and
`ADMIN_STORE_SNAPSHOT=off` restores Layer 1 exactly (L2-d). Routes on an
explicit allow-list send a weak `ETag`, and the tag is computed from the
build, the generations, the store versions, the settings generation, the FX
table version, the query, the Berlin date and the user. That happens
**before the body is built**, so a matching `If-None-Match` returns 304 and
skips the work as well as the bytes (P3-c). Every `/api` response's
`Server-Timing` gains `app;dur` and `snap;desc=hit|miss|off` (P3-d). The
idle tab stops re-reading `/market/updates` on every `market` event.

How it works in idea: the snapshot is consulted only through the existing
`read_memo` seam, and only inside a `@read_scope` view of the admin. The
backing hook is installed by the admin app, so the bot and the refresher
never see the snapshot. A request trusts the snapshot only when the switch
is on, the listener is connected, and the request's generation token and
store versions both match the snapshot's. Any other state, or any
exception, means the request loads directly as today. Each candidate route
is admitted by its own audit task. Each audit lists every payload field and
shows that none depends on a live price, an FX quote fresher than the daily
row, the wall clock below day resolution, or a setting outside the key. A
route that fails is dropped and recorded, not forced.

What it leaves alone: `/dashboard`, `/live`, `/market/*` and every other
route keep `Cache-Control: no-store` and get no ETag. The SQL, the worker
count, every response body and every golden stay byte-identical. There is
no schema change: `version()` reads the existing `updated_at`. There is no
UI layout change, and no SPA change for the ETag (a browser revalidates on
its own and hands Angular a 200 with the cached body).

Success is measured on production with the committed browser probe
(`scripts/ops/admin_browser_probe.py --date 2026-11-03`) run during a scan.
The table lands in v206 `## Results` as "Plan 3 after". The measures are the
`/trades` p90 for the closed view, the share of `snap;desc=hit` responses,
and the idle-tab rate, all set against Plan 2's 11.1 s and 16.5 per minute.

## Architecture

- **Versions** (V218-1): `TradeRepository.version()` and `JournalRepository.version()` twin `PlanRepository.version()` (`(count, max(updated_at) iso)`). A two-connection test reproduces the stamp gap (`clock_timestamp()` is statement time, so a transaction can commit under an older stamp than a concurrent one). That evidence is recorded for the two existing callers, and V218-6 adds the generation to their keys.
- **Generations** (V218-2): leaf module `swingbot/core/infra/store_generation.py` holds the process-wide counters `trades`, `journal` and `settings`, plus the listener's `connected` flag. `config.reload()` bumps `settings` whenever it changed a value. The admin reloads by `.env` mtime per request (`admin/app.py:269`) and gets no SIGHUP. New Field `ADMIN_STORE_SNAPSHOT` (`on|off`, default `on`).
- **Listener** (V218-3): `SnapshotListener(DbEventListener)` on channels `trades` and `journal`, independent of the SSE broker. It is started lazily on the admin's first non-testing request (`preload_app = False`, so the thread lives in the worker). `on_notification` bumps the channel's generation before the debounce. A (re)connect bumps all generations and sets connected. A lost connection clears it.
- **Snapshot** (V218-4, V218-5): `swingbot/core/infra/store_snapshot.py` stores the loader's value per key for `SNAPSHOT_KEYS = {TRADE_ROWS, TRADES, PLANS, NOTED_IDS}` under one lock, with one rebuild at a time. The validity token is `(store_generation.token(), request_versions())`, and the versions are read once per request (`begin_request()` from `request_timing._begin`). `read_memo` stays a leaf: it gains `set_backing(fn)`, and the admin app calls `store_snapshot.install()`. `read_memo` keeps handing every caller shallow copies.
- **Conditional responses** (V218-7, V218-8, V218-10..13): `swingbot/admin/build_identity.build_version()` hashes `VERSION.json` and appends `SWING_BOT_IMAGE` from the environment when present. `swingbot/admin/api_v1/conditional.conditional(route_key, admit)` is a view decorator placed under `@require_auth`, so a 401 never reaches it, and above `@read_scope`. It computes the tag first and returns a bodiless 304 on a match. On a 200 it sets `ETag: W/"…"` and `Cache-Control: private, no-cache`, and `_no_store`'s `setdefault` leaves that alone. Any other status, a fresh request (`X-Swingbot-Fresh: 1`), the switch off, the listener down, an `admit(args)` false, or an exception gives no ETag.
- **Server-Timing** (V218-9): `total;dur=…, db;dur=…;desc="N statements", app;dur=…, snap;desc=hit|miss|off`. Here `app` is total minus db, and `snap` comes from `store_snapshot.request_state()`.
- **Idle tab** (V218-14): `live-values.store.ts` reads `market` through the shared 30 s throttle. Its 60 s poll fires only when no sync ran in the last 60 s, so it still notices a dead refresher.

**Tech stack:** Python 3.11, Flask (`api_v1` blueprint), SQLAlchemy Core on Postgres LISTEN/NOTIFY, pytest (suites `admin-perf`, `admin`, plus the `tests/db/` and root config tests' suites); Angular signal stores, Vitest via `node frontend/scripts/ng-test.mjs frontend --include <spec>`.

## Global Constraints

- Every response body and every golden under `tests/admin_perf/golden/` stays byte-identical with the snapshot on and off. Goldens are never regenerated. New keys would go in `ADDED_POINTERS`, and this plan adds none.
- The snapshot stores **raw records only** (the loaders' values). Anything derived from the clock is computed per request: days held, open P&L, `today`, `held_hours`.
- The snapshot is served only when **all** of these hold: `config.ADMIN_STORE_SNAPSHOT == "on"`, `store_generation.connected()`, `read_memo.active()`, and a token equal to the stored one. Otherwise the request loads directly (Layer 1). A failing version query or rebuild is logged through `swallowed(log, "ops.admin.snapshot", exc)` and that request loads directly. A snapshot the checks cannot vouch for is never served.
- A call that passes `conn=` (a transaction) never reads through the memo or the snapshot. This is unchanged.
- ETag: weak (`W/"<sha256 hex, 32 chars>"`). Its inputs are exactly `build_version()`, `store_generation.token()` (trades, journal, settings), `PlanRepository.version()`, `TradeRepository.version()`, `JournalRepository.version()`, `fx_daily_rate_repo().version()`, `normalised_query(args)`, `fx_convert.berlin_today().isoformat()` and the principal `(role, username, user_id)`. The route key is also hashed, so two routes never share a tag.
- A 304 is sent only for an allow-listed route with a computed tag. A 304 has no body and carries the same `ETag` and `Cache-Control: private, no-cache`. A 400, 401, 403, 404 or 5xx never carries an ETag. Non-allow-listed routes keep `no-store`.
- `/dashboard` is excluded by the spec. So is any `/trades` query shape that can include open rows. The allow-list is per (route, query shape), and `tests/admin_perf/test_conditional_routes.py` asserts it exactly.
- `X-Swingbot-Fresh: 1` bypasses the ETag, since the client asked for fresh market data.
- `Server-Timing` keeps `total` and `db` first and unchanged. `app;dur` and `snap;desc` are appended. `test_server_timing.py`'s regex and exact string change in the same commit. No test asserts the whole header on a production capture, because Cloudflare appends `cfExtPri`.
- Every function written or changed stays at cyclomatic complexity < 15 (`scripts/dev/complexity_gate.py`). `api_v1/trades.py:list_trades` is E(32) in the baseline and must not get worse. The ETag lives in a decorator, never as arms inside the view.
- Every task ships its own tests. Verification is narrow: `python scripts/dev/testrun.py file <test>`, `... suite admin-perf`, `... changed`, `node frontend/scripts/ng-test.mjs frontend --include <spec>`. **No task runs the full suite; CI does after the push** (CLAUDE.md wins over v205's "last task is the full suite").
- Tests that reach Postgres run `/replicate-prod-db` first, once per session, against the shared `swing-db` container (port 56789, `.env` credentials never printed). Never a per-task database.
- A test that starts a listener uses an injected `listen=` fake or the `db_engine` fixture. No test leaves a listener thread running: fixtures call `snapshot_listener.stop()` and `store_snapshot.reset()` / `store_generation.reset()` on teardown.
- Implementation runs in worktree `.claude/worktrees/2026-11-06-v218-admin-snapshot-etag` (branch of the same name), named in every dispatch. Nothing is committed on `main` except by V218-15's merge.
- Production is read-only for this plan (`scripts/ops/ssh-hetzner.sh`, read-only commands only). The partner runs the deploy per `docs/deploy/DEPLOY_HETZNER.md`. A direct VM change follows `mirror-prod`. Credentials stay inside the probe and are never echoed.

## Handoff

Controller decisions, made 2026-11-06. These are deviations from the spec text, with reasons:

1. **Always-on snapshot listener.** `DbEventListener` runs only while an SSE tab is open: `EventBroker.subscribe()` starts it on the first subscriber and `_release()` stops it on the last (`admin/events/broker.py:253-305`). The snapshot therefore gets its own listener, `SnapshotListener` (V218-3), started with the admin app in its one gunicorn worker. v205 L2-b's "a listener that is not connected bypasses the snapshot" applies to *that* listener, through `store_generation.connected()`.
2. **Journal joins the inputs.** `/trades` reads `has_note` (`_noted_ids`, memo key `NOTED_IDS`), and the calendar routes read `JournalStore().entries()`. `journal_entries` NOTIFYs on channel `journal`, so a journal change bumps generation `journal`, and `JournalRepository.version()` joins both the snapshot token and the ETag inputs. `/trades` is admitted only per query shape: closed-only filters and no sort that prices open rows, per its audit (V218-10).
3. **Settings generation on `config.reload()`.** The admin gets no SIGHUP. It reloads through `config.auto_reload_if_changed()` on every request (`admin/app.py:269`), so the settings generation is bumped inside `config.reload()` whenever a value changed. The spec's "SIGHUP settings reload" test becomes "a `.env` change picked up by `auto_reload_if_changed` gives a 200".
4. **Image tag.** `build_version()` uses `SWING_BOT_IMAGE` from the environment when present, else `VERSION.json` alone. V218-7 checks on the VM, read-only through `scripts/ops/ssh-hetzner.sh`, that the admin container sees it.
5. **A route whose audit fails is dropped** from the allow-list and recorded in v206 `### Plan 3 route audits (V218-10..12)`, never forced.

Planner notes (plan-writer, same day), flagged for the controller:

- **FX input:** the tag uses `fx_daily_rate_repo().version()`, which is `(count, max(snapped_at))` and already exists, in place of the spec's "latest date". It moves whenever the latest date moves, and also on a re-snap, so it is strictly safer and no new accessor is needed.
- **`/trades` audit and FX source:** with the refresher off, closed-row FX can come from the pair frame (`fx.fx_rate` → `rate_before`), which the table version does not cover. A trade closed today can change its converted amount when yesterday's bar lands. V218-10 therefore makes `closed_only_query` require `admin_refresh.refresher_on()` (production runs with it on). This is an audit finding, written out in the task.
- **Calendar audits are expected to drop both routes.** Both bodies carry `as_of = datetime.now()`, documented as "the time this filtered view was composed" (`page_bodies.py:354`, `calendar.py:157`). That is a `generated_at`-style stamp below day resolution, which the spec's rule excludes. `/calendar/pnl` also carries refresher `market_meta` (`computed_at`, `refreshing`). V218-11/12 pin the evidence in a test and record the drop. They admit only if the code proves otherwise, and changing `as_of` would be a payload change outside this spec.
- **No full-suite task** (CLAUDE.md "Naming specs and plans" overrides v205's Testing line).
- The snapshot is installed only by the admin app (`read_memo.set_backing`), which keeps `read_memo` a leaf module. The bot and the refresher never import `store_snapshot`.
- `snap;desc` semantics: `off` means the switch is off or the request was bypassed (listener down, version query failed, no read scope). `miss` means at least one key was rebuilt this request. `hit` covers everything else, including a 304 that read nothing.
