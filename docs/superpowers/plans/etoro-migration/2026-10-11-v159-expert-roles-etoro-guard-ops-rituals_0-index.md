**Goal:** Add four expert seats (`execution-specialist`, `compliance-reviewer`, `ux-designer`, `sre`; 9 → 13), a demo-only eToro guard in two layers (a session hook rule that also covers PowerShell, MCP tools and `.env` edits, and `swingbot/core/broker/guard.py:assert_demo` with an admin-UI-only unlock), the `order-safety` skill and `reconciler` agent contracts, and the ops/UI rituals (`/soak` with its locked pre-registration block, `/incident`, the `frontend` and `chart-render` skills, the `ui-verifier` agent).

**Architecture:** Part A is markdown plus registry tests: four role skills in the v145 shape, registered in `test_role_skills.ROLES`, `test_skill_shape.TIER_1_AND_3`, `test_agent_shape.EXPERT_ROLES`, `expert-reviewer.md` and the `skills-tools.md` roles table, with a new `compliance-publication.md` reference doc and a `Places-orders:` spec-header check. Part B adds one total, never-raising hook rule `_rule_etoro_real_account` reached through a new MCP prefix table, the shared shell-rule list (now registered under `PowerShell` too), and per-file patch sections for `apply_patch`; then a new package `swingbot/core/broker/` holding only `guard.py`, two hot-reloaded settings, a server-side sign-off check in `save_settings`, an `env_set.py` refusal and an SPA dialog that makes the partner type the sign-off date. Part C is skills, agents, a generalised VM sampler and a second hook rule `_rule_soak_prereg_locked`. Order-risk checks (`sizing.py`, `pre_open.py`, `ETORO_MAX_TRADE_USD`, `ETORO_ACCOUNT_SIZE`) are v160's and are not built here.

**Tech Stack:** Python 3.11 stdlib (hooks), pytest via `scripts/dev/testrun.py`, Flask admin API, Angular 20 signals + vitest (SPA), bash (VM scripts), radon.
