## Goal

The partner trades from the simple Discord channel: new setups, fills,
cancels, stop moves, TP1, results and near-stop/TP warnings all land there.
When bomeo-capital.com is open on a phone, tablet or desktop they want to
*hear* each of those posts without watching Discord. Nothing about which
alerts the bot produces, their content or their timing changes; this plan
adds a second, spoken surface for posts that already go out.

Once shipped, the bot records every simple-channel post that Discord accepted
into a new `feed_posts` table (kind, ticker, a short spoken headline such as
"New long alert, AAPL, buy at 187.50"). The table's NOTIFY trigger raises a new
`feed` SSE event; every open admin tab fetches the rows after the last id it
has seen, drops the kinds the partner silenced, and speaks the rest with the
browser's free `speechSynthesis`, one at a time. A voice chip in the top bar
shows whether speech is locked (browsers need one tap per page load), live,
muted, blocked or unavailable. A new "Voice notifications" block in System →
Settings holds a master switch, one switch per family and per kind (the Watch
family off by default), a voice picker, a rate slider and preview buttons, all
stored per browser under `swingbot.voice.v1`.

It leaves alone: what the bot posts, the history-channel fallback copy (not
recorded), every other channel, server-side TTS and push notifications for
closed tabs. A post made while no tab was open is never spoken later. The
recorder never raises and never stalls the bot loop for longer than the side
engine's statement timeout; `FEED_POSTS_ENABLED=false` silences the site
without touching Discord.

Success is measured by tests, not by edge: one row per accepted
simple-channel send and none for a failed send or the history copy; a
rollback-safe migration whose downgrade drops table and trigger; an hourly
prune that issues no `DELETE` when nothing is old; an SSE contract that keeps
`feed` in step on both sides; a notifier that never replays a backlog, never
overlaps speech and caps a reconnect burst at five headlines plus "and N
more"; and a chip and settings block that pass the layout audit at 390, 768
and 1440 px.

## Architecture

- **Bot side (Part 1).** `swingbot/core/db/migrations/versions/v227_001_feed_posts.py`
  creates `feed_posts` + index + the shared statement-level NOTIFY trigger on
  channel `feed`; three registries change together (`notify.CHANNELS`,
  `events.TABLE_CHANNELS`, `schema.METADATA`). SQL lives in
  `swingbot/core/db/repositories/feed_posts.py`; the Kind → phrase table and
  builder live in `swingbot/core/presentation/feed_headline.py`; the glue
  `record_feed_post` in `swingbot/core/infra/feed_posts.py` imports both
  lazily, writes through `side_engine.side_connection()` (autocommit, fail-fast)
  and runs the hourly prune. It is called synchronously inside the `try`, right
  after `log_posted`, in the two simple-channel senders:
  `swingbot/commands/scanning/alerts.py:_mirror` and the feed branch of
  `swingbot/core/scanning/lifecycle_embeds.py:_send_instruction`.
- **Admin side (Part 1).** `swingbot/admin/api_v1/feed_posts.py` serves
  `GET /api/v1/feed-posts` (paging after an id) and
  `GET /api/v1/feed-posts/kinds` (families, kinds, Discord labels, spoken
  phrases and samples), both through `require_auth`, readable by viewers.
- **SPA (Parts 2–3).** New folder `frontend/src/app/voice/`: `VoicePrefs`
  (localStorage), `VoiceSpeaker` (the only code touching `speechSynthesis`;
  owns the chip state machine and the queue) and `VoiceNotifier` (SSE `feed`
  → fetch → filter → speak). `sb-voice-chip` sits in the shell's
  `.status-cluster` at every width. `sb-switch` is a new `role="switch"`
  primitive in `frontend/src/app/ui/`. `sb-voice-settings` is a standalone
  component embedded in `settings-tab.ts` outside its `<sb-async>`, so it never
  waits on, or errors with, the `/system/settings` payload.

## Global Constraints

- Table `feed_posts`: `id bigserial PK`, `posted_at timestamptz NOT NULL default now()`, `kind text NOT NULL` (a `Kind` member name), `ticker text NULL`, `headline text NOT NULL`, `*standard_columns()` (`doc`, `updated_at`); promoted `("posted_at", "kind", "ticker", "headline")`, one `PROMOTION_REASONS` line (≤ 100 chars) each; index `feed_posts_posted_at_idx` on `posted_at`.
- Revision `revision = "v227_001"`, `down_revision = "v209_001"` (re-run `python -m alembic heads` first; if the head moved, stop and report). It restates `("feed_posts", "feed")` (frozen; never imports `TABLE_CHANNELS`) and carries a top-level `ROLLBACK_SAFE = "..."` string literal. Downgrade drops the trigger, then the table.
- Channel / event name is exactly `feed`, appended last in `notify.CHANNELS` and in the TS `EVENT_NAMES`.
- Config key `FEED_POSTS_ENABLED`: `type="checkbox"`, `default="true"`, section `"Discord Alerts"`, hot-reloadable, `search_class` left at the default `"excluded"`. Off: `record_feed_post` returns before any database work; Discord sending is untouched.
- `record_feed_post` never raises (every failure goes through `swallowed(log, "feed_posts.record", exc, level=logging.DEBUG)` or `"feed_posts.prune"`), writes only through `side_engine.side_connection()`, runs synchronously (no thread, no task: single-writer ordering), and imports `swingbot.core.presentation` and `swingbot.core.db.repositories.feed_posts` only inside the function. A post with no resolvable kind records nothing.
- Retention: `RETENTION_DAYS = 7`, `PRUNE_EVERY_S = 3600`, gate on an in-process `time.monotonic()` timestamp; the prune runs `SELECT 1 ... WHERE posted_at < now() - interval '7 days' LIMIT 1` and issues the `DELETE` only when that finds a row.
- Only the two simple-channel sends record, only after `send` returned; the history copy and every history-only send record nothing.
- Spoken text never contains `None`, `nan` or an empty clause; a kind with no table entry falls back to `kind.label.lower()`. Families listed and toggleable: `NEW_SETUP`, `ENTRY`, `MANAGE`, `WATCH`, `RESULT` (never `SYSTEM`, `BOOK`). `WATCH` defaults off, every other family on.
- API: `GET /api/v1/feed-posts?after=<id>&limit=<n>` → `{"items": [...], "latest_id": int}` oldest first; `limit` default 20, values above 50 clamp to 50, `limit < 1` or non-integer `after`/`limit` → 400 `{"error": {"code": "invalid", ...}}`; no `after` → `"items": []`. `latest_id` is `0` on an empty table.
- localStorage key `swingbot.voice.v1`, value `{enabled, kinds: {<KIND>: bool}, voice, rate}`; every read/write wrapped in try/catch; garbled → defaults; a kind missing from the map takes its family default. Rate range 0.8–1.4, step 0.05, default 1.0.
- User-facing copy, exactly: chip "Enable voice" / "Voice on" / "Voice muted" / "Voice blocked" / "No voice on this browser"; Settings block heading "Voice notifications"; master switch "Speak simple-channel posts"; disabled reason "Turn on voice to choose kinds"; unlock phrase "Voice notifications on"; voice picker loading "Loading voices…"; button "Test voice"; reconnect tail "and N more" (N a number).
- Three-device rule (`docs/claude/ui-design.md`): the chip is in the top bar at 390, 768 and 1440 px (never in a menu), 44 px hit area (`sb-hit`), text label beside the icon, `aria-label` names its action; every switch row and the rate thumb are ≥ 44 px on phone; groups one column on phone, two on tablet and desktop; labels wrap, never truncate. No `title=` attribute for explanations (`title-usage.spec.ts`): use `sb-hint`.
- No colour literal in `.ts`/`.html` under `frontend/src` outside `styles/` (`primitives.spec.ts`). Specs read files from `process.cwd()` (`frontend/`). jsdom has no `speechSynthesis`: every spec touching speech injects a fake through the `SPEECH` token, never `window`.
- Every function stays below cyclomatic complexity 15 (`python scripts/dev/complexity_gate.py`); `_mirror` and `_send_instruction` gain one call each.
- Per-task verification is the narrow run: `python scripts/dev/testrun.py file <test>`, `node frontend/scripts/ng-test.mjs frontend --include <spec>`. **No task runs the full suite; CI does after the push.** DB tests run `/replicate-prod-db` once per session first (shared `swing-db`, port 56789).
- Tests stay in existing directories (`tests/db/`, `tests/presentation/`, `tests/infra/`, `tests/commands/`, `tests/scanning/`, `tests/admin/`, `tests/scripts/`, `tests/test_config_*.py`); no new `tests/` directory, no `suites.toml` edit.
- Implementation runs in worktree `.claude/worktrees/2026-11-12-v227-voice-notifications` (branch of the same name). Name it in every dispatch. Several scoped commits, never one big one. Nothing reaches `main` except through V227-15's merge after the partner's yes.
- `VERSION.json`: ui minor, bot patch, applied by `/close-out` in V227-15 (then regenerate `version_history.json`); no earlier task edits it.

## Review Focus

1. **A failed send that still speaks.** The recorder must sit after `send` inside the `try`. Pinned by V227-5 (failing `_Chan` → zero `record_feed_post` calls, in both senders; history copy → zero).
2. **The bot loop stalling on a slow database.** Pinned by V227-4 (recorder uses `side_connection`, a raising connection is swallowed, `FEED_POSTS_ENABLED=false` touches no connection).
3. **An hourly empty `feed` event to every tab.** Pinned by V227-2 (`prune` with nothing old executes no `DELETE`) and V227-4 (prune at most once per `PRUNE_EVERY_S`).
4. **Rollback refused or dishonest.** Pinned by V227-1 (`scan_upgrade(source).safe` with a non-None override; downgrade/upgrade round trip; single head).
5. **Speech replayed or overlapping.** Pinned by V227-9 (no backlog at start, resume from last id after resync, cap 5 + "and N more") and V227-8 (one utterance in flight; mute cancels and clears).
6. **The SSE taxonomy drifting.** Pinned by V227-1 (`EXPECTED_EVENTS`, `CHANNELS`, `EVENT_NAMES` and `event-stream.spec.ts` change in one commit).
