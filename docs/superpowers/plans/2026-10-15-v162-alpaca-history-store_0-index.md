**Edge:** none (integrity)

**Goal:** A third OHLCV store, `data/market_data/{15min,hourly,daily}/`, backfilled from Alpaca's SIP tape (2016 to now, `Adjustment.ALL`) by a rate-safe, resumable, identity-checked script that runs on the VM, kept current by a weekly lockstep update, read through one seam (`history_store`) and made the default training data (`TRAINING_DATA_SOURCE=alpaca`) for every backtest, grid and the admin Tuning page, with provenance on every result and a reproducible three-leg re-baseline.

**Architecture:** The provider gains one public method (`AlpacaProvider.history_bars`); the backfill logic lives in a small package `scripts/data/alpaca_history/` (guards, identity, store I/O, fetch, update) driven by the CLI `scripts/data/fetch_alpaca_history.py`. Reading is split in two: `swingbot/core/marketdata/history_store.py` (pure read of the store and its manifests) and `swingbot/core/marketdata/training_data.py` (the source switch, exclusions and provenance), which `scripts/data/fetch_backtest_data.load_cached` and `backtest_wf._frame_for` delegate to, so every script that reads training bars goes through one switch. The registry and the ledger gain a `data_source` field that keeps the yfinance and Alpaca populations apart.

**Tech Stack:** Python 3.11, pandas/numpy, alpaca-py 0.44.0 (`StockHistoricalDataClient`, `StockBarsRequest`, `DataFeed.SIP`, `Adjustment.ALL`), pytest via `scripts/dev/testrun.py`, radon, bash (VM ops through `scripts/ops/ssh-hetzner.sh`), Angular + Vitest (admin Tuning page).

## Global Constraints

- **Bump: bot patch.** Only `/close-out` touches `VERSION.json` / `version_history.json`. No alert, embed or live-scan change: the live scan, `data_refresh`, `backtest_cache.ensure_cached`, the root `market_data/` cache and every alert stay as they are and never read `data/market_data/`.
- **Store layout (spec §1, binding):** `data/market_data/{15min,hourly,daily}/{SAFE}.csv`, `SAFE = data_store.safe_symbol(ticker)`; columns `Open,High,Low,Close,Volume`; intraday index column `Datetime` = naive **America/New_York wall-clock, bar start**; daily index column `Date` = naive date. 15min stores **all sessions** (04:00–20:00 ET); `hourly` is built from Alpaca **30-minute** bars with `providers.base.to_yf_hourly` (09:30-anchored, RTH only, last bar 15:30–16:00 is a half-hour); `daily` is native daily through `to_yf_daily`. Alpaca's native `1Hour` bars are never used. The store root is `history_store.store_root()`: env `HISTORY_STORE_DIR` when set (read on every call, never at import), else `Path(config.DATA_DIR) / "market_data"`.
- **Source (binding):** `DataFeed.SIP`, `Adjustment.ALL`, `end = min(end, now − SIP_DELAY)`, one calendar year per `history_bars` call. Live callers of `AlpacaProvider._bars` are unchanged.
- **Manifest shape** (`data/market_data/{tf}/_manifest.json`, written only by `alpaca_history.store_io.save_manifest`, read by `history_store.manifest`):
  ```json
  {"timeframe": "daily", "feed": "sip", "adjustment": "all", "updated_at": "2026-10-18T06:31:02Z",
   "hash": "<sha256 hex over the sorted lines '<TICKER>:<sha256 or ->'>",
   "tickers": {"AAPL": {"status": "ok", "start": "2016-01-01", "first": "2016-01-04", "last": "2026-10-16",
                        "rows": 2716, "sha256": "<hex>", "fetched_at": "2026-10-18T06:12:40Z",
                        "identity": {"status": "ok", "median_ratio": 1.0001, "overlap": 2710, "dropped_before": null}}}}
  ```
  `status` is `ok`, `skipped: <reason>` or `flagged: <reason>`; `start` is the requested `--start`; intraday `first`/`last` are `YYYY-MM-DD HH:MM`; a skipped ticker has `rows: 0`, `sha256: null`, `first`/`last`/`identity` null. Intraday entries copy their ticker's daily `status` and `identity`.
- **Identity check (binding):** reference `data/backtest_cache/{SAFE}.csv`, fallback root `market_data/daily/{SAFE}.csv`; median of fresh Close / reference Close over the overlap, NaN-safe, tolerance `ALPACA_TOLERANCE = 0.005` imported from `scripts/ops/market_cache_repair.py`; overlap `< 250` → `flagged: short-overlap` (never a pass); no reference → `flagged: no-reference`; disagreement → `flagged: price-mismatch`. Bars before the reference's first bar are dropped and `identity.dropped_before` records that date. A flagged ticker is still written.
- **Rate and hours (binding):** token bucket `RATE_PER_MINUTE = 120`; a 429/5xx (or no status) backs off `2 s × 2^attempt` for at most 5 retries; `AlpacaAuthError` stops the run (exit code 2). During the US regular session (`swingbot.core.market.session.is_regular_session`) the script refuses unless `--force-hours`. A run over 15 minutes prints a percent. Disk guard: refuse when free space minus the estimate would drop below `MIN_FREE_BYTES = 3 * 1024**3`.
- **Update (binding):** `--mode update` refetches each ticker's full daily history, and if any stored daily close differs from the fresh one by more than `BASIS_RTOL = 1e-6` relative (or a stored row vanished), **all three timeframes of that ticker are refetched in full and replaced together**; otherwise each timeframe appends only bars after its last one. An unchanged day writes nothing (no file, no manifest `updated_at` change).
- **Training switch (Amendments, binding):** config `TRAINING_DATA_SOURCE` (`alpaca` | `yfinance`, default `alpaca`, section "Data Sources", `select`). `training_data.select(name)` resolves `None` to the config value; `alpaca` with no `daily` manifest raises `history_store.MissingStoreError` naming the missing path (never a zero-ticker run); a ticker whose manifest status is not `ok`, or whose file is missing, is excluded and recorded with its reason. A run never mixes sources. Rollback is one `.env` line, `TRAINING_DATA_SOURCE=yfinance`.
- **Provenance (Amendments, binding):** the result JSON shapes do not change. Every `--json` output gets a sidecar `<out>.provenance.json` (`training_data.write_provenance`) holding `data_source`, `feed`, `adjustment`, `manifest_hash`, `store_dir`, `excluded` (`{ticker: reason}`). `tune_strategy.py --json` payloads gain the keys `data_source` and `provenance` (that payload is an arbitrary dict, nothing replays it).
- **Registry and ledger (Amendments, binding):** new registry rows carry `data_source`; `merge_registry` keys on `(source, strategy, horizon, data_source)` with a missing value meaning `yfinance`; old rows are never rewritten. `get_badge` takes the row whose `data_source` equals `TRAINING_DATA_SOURCE`, falls back to the `yfinance` row, logs which one it used (once per key), and never blends. The ledger gains the **optional** field `data_source` (`OPTIONAL_LEDGER_FIELDS`); an absent value means `yfinance`; old rows are not rewritten.
