**Goal:** Route every Alpaca and yfinance request in `swingbot/` (bot, spawned workers, admin) through one shared, Postgres-coordinated fetch layer with per-asker freshness windows, cross-process single-flight, one money-first budget and per-call counters; make the scan's daily cache warm with a proven delta splice; rebuild every live-priced plan from a last-second quote right before it posts; and feed the admin tape from one shared copy with labelled ETF proxies.

**Architecture:** A new package `swingbot/core/marketdata/shared/` holds the layer: `kinds.py` (data kinds, askers with priority and window, `Entry`, `QuoteDetail`), `counters.py` (D9), `budget.py` (D6 shared token buckets and breaker), `layer.py` (`get` for JSON-cacheable kinds, `lease` for bar writers) and `tape.py` (D7). Its Postgres state lives in three new tables behind `swingbot/core/db/repositories/market_shared.py`, reached over a per-process side engine (`swingbot/core/db/side_engine.py`) with a short statement timeout, so every Postgres touch fails open. Bars stay on disk: `swingbot/core/marketdata/daily_delta.py` owns the D3/D4 delta fetch, the per-symbol `.meta.json` sidecar and the single atomic writer, over two caches with one basis each: the new Alpaca-basis `market_data/daily_alpaca/` for the scan's Alpaca-served symbols, and the unchanged yfinance-basis `market_data/daily/` for everything else. The D5 rebuild is one function in `swingbot/core/planning/rebuild.py`, fed by `swingbot/core/scanning/requote.py` in the main scan and the SHORT lane. Each part sits behind its own flag; every flag off restores today's code path.

**Tech Stack:** Python 3.11, pandas, yfinance 0.2.66 (pinned), alpaca-py, SQLAlchemy Core + Alembic on Postgres, discord.py tasks loops, Flask, pytest via `scripts/dev/testrun.py`; Angular ~21.2 (standalone, zoneless, signals), vitest via `ng test`; Playwright via `frontend/scripts/browse.mjs` for the three-width pass.

## Global Constraints

- **Flags, one per part** (`swingbot/config.py`, section "Data Sources", all `hot_reloadable=True`, all in `.env.example`): `MARKETDATA_LAYER` select `off`/`count`/`on` (code default `off`; production ships `count`); `DAILY_DELTA_FETCH` checkbox (default false, D3+D4); `PLAN_REBUILD_ENABLED` checkbox (default false, D5); `TAPE_SHARED_ENABLED` checkbox (default false, D7). **Every flag off restores today's code path exactly**; a test per flag pins that (the off branch calls the pre-v171 function unchanged).
- **Mode semantics:** `off` = no layer code runs; `count` = pass-through, every provider call made exactly as today, counted by (provider, kind, asker, outcome) and flushed hourly, no cache read, no lease, no budget; `on` = cache, lease single-flight, shared budget and breaker.
- **Freshness defaults (D2, `config.py`, seconds):** `QUOTE_MAX_AGE_REQUOTE_S` 5, `QUOTE_MAX_AGE_MONITOR_S` 15, `QUOTE_MAX_AGE_SCAN_S` 15, `QUOTE_MAX_AGE_DASHBOARD_S` 15, `QUOTE_MAX_AGE_ADMIN_S` 60, `INDEX_QUOTE_MAX_AGE_S` 60, `EARNINGS_MAX_AGE_S` 21600, `REBUILD_PRICE_MAX_AGE_S` 60, `TAPE_STALE_FALLBACK_S` 180. Ticker metadata is persistent (no expiry). A cached entry older than the asker's window is refetched, never served (except the tier 3-5 deadline / budget-deferred rule below).
- **Askers and priority (D6):** `STOP_MONITOR` 1 (trade monitor, plan manager), `REQUOTE` 2 (pre-post re-quote), `SCAN` 3 (live scan, SHORT lane), `BACKGROUND` 4 (refresh loop, earnings, re-anchor, tape feed), `ADMIN_DASHBOARD` 5 (15 s), `ADMIN_PAGE` 5 (60 s). A request carrying the SPA's fresh mark runs as its own admin asker at tier 5 with max age 0.
- **Budget (D6):** one bucket per provider shared by all processes: Alpaca `ALPACA_BUDGET_PER_MINUTE` 150, yfinance `YF_BUDGET_PER_MINUTE` 60 (pacing default, builder's call). A tier may take a token only while the bucket keeps its reserve after the take: tiers 1-3 reserve 0, tier 4 reserve 25 % of capacity, **tier 5 reserve 50 % of capacity**, so no admin request (reloads included) can ever take budget tiers 1-3 need. A short budget gives tiers 4-5 the freshest cached value with its age (outcome `budget-deferred`); tiers 1-3 are never deferred.
- **Fail open everywhere (D1):** cache read, lease and budget each run under `MARKETDATA_PG_TIMEOUT_MS` 250 (statement timeout on the side engine). Any error or timeout: the asker fetches directly, one `log.warning` per minute per (operation, error class), counted as outcome `failed` only if the provider call itself fails.
- **Single-flight:** lease rows in `market_cache` (`lease_holder`, `lease_until`, lease `MARKETDATA_LEASE_SECONDS` 30), so a dead holder never strands waiters. When a waiter's deadline passes, tiers 1-2 fetch for themselves; tiers 3-5 get the last cached value with its age, or fail as today.
- **Connections:** the layer never uses the main pool. `side_engine` is `pool_size=1, max_overflow=1` in the bot and admin processes and `pool_size=1, max_overflow=0` in spawned workers (`multiprocessing.parent_process() is not None`), opened lazily. Peak per scan: bot 2 + concurrent `_run_bounded` workers (each `max_workers=1`, at most 3 alive at once: scan phase, trade monitor, plan manager share one after V171-10, so 2) + admin 2 = **at most 7 side connections**, beside the existing main pools; one round trip per cache hit; no CPU-bound work added per scan (V171-6 pins the round trip count).
- **Cache basis (D4, partner's choice, spec 1b2fb952): one basis per file, two caches.** (1) **New `market_data/daily_alpaca/<SYMBOL>_daily.csv`** (constant `data_store.ALPACA_DAILY_DIR`), basis **`"alpaca-all"`**: Alpaca SIP daily bars, `Adjustment.ALL`, 10 years deep (`DEFAULT_HISTORY_PERIOD`, floor `alpaca_provider.HISTORY_FLOOR`), the depth the scan gets today. It serves every symbol the scan routes to Alpaca (`base.is_alpaca_eligible` and `ALPACA_ENABLED`). Its window and full fetches go to Alpaca (`router.daily_bars` / a ranged `_bars` call), so the scan stays on Alpaca with one small "today's bar" call per scan chunk. **Only `daily_delta.write_daily` writes it**, under the key's lease; its callers are the scan crawl (V171-13), the plan manager's forming-bar refresh (V171-14) and the weekly re-anchor (V171-15). (2) The existing **`market_data/daily/*.csv` is unchanged**: yfinance `auto_adjust=True`, full history since listing, still written by its existing writers (`data_store`, `data_refresh`, all through `atomic_write_csv`). With the flag on, the scan uses it only for symbols that are not Alpaca-eligible (window and full fetch via `yf_safe.download(auto_adjust=True, actions=True)`). Every other reader (admin charts and risk, research, `data_refresh`, training) keeps reading it as today. Frames never cross caches: a cold Alpaca frame is never written into `market_data/daily`, and a yfinance frame never into `daily_alpaca`. Each CSV has a sidecar `<csv stem>.meta.json` with `basis`, `last_full_fetch`, `last_verified`, `anchor_date`, `anchor_close`. `daily_delta.basis_for(ticker) -> str` picks the file. Both dirs sit on the shared `./market_data` bind mount, so the admin can read `daily_alpaca` too, but it never writes there.
- **Delta rule (D4), per file on its own basis:** window = from `last_verified` minus 3 overlap bars to today, capped at `DELTA_WINDOW_MAX_DAYS` 30 calendar days (a longer gap = full refetch). Full refetch from **that file's own provider** when any of these holds: (a) **an event trigger**. For `yfinance-auto_adjust`: any non-zero `Dividends` or `Stock Splits` in the window dated after `last_full_fetch`. For `alpaca-all`: the **anchor-bar fingerprint**. `anchor_date` is the file's first bar on or after `ALPACA_ANCHOR_DATE` (`"2017-01-03"`, inside the 10-year depth, so every later split or dividend rescales it). Its fresh `Adjustment.ALL` close is fetched once per trading day per symbol (the first delta of the day, batched into one ranged multi-symbol request for all symbols due) and compared with `anchor_close`; any change bigger than `DELTA_OVERLAP_TOLERANCE` triggers. (b) Fewer than 3 overlap bars. (c) Any overlap close differing by more than `DELTA_OVERLAP_TOLERANCE` = `1e-4` relative. (d) A missing or unreadable sidecar. (e) A sidecar `basis` that is not the file's basis. A refusal never takes `history_splice`'s live-only path, and the result is never shallower than the file. Writes are unions (`adjustments.merge_adjusted`, fresh rows win on overlap); an `alpaca-all` full refetch replaces only the 10-year span it returns.
- **One tolerance home:** `adjustments.py` owns `ADJUSTMENT_MISMATCH_TOLERANCE` (0.01, behaviour unchanged), `MIN_OVERLAP_BARS` (3) and `DELTA_OVERLAP_TOLERANCE` (1e-4); `data_refresh.py` and `history_splice.py` import them, no copies.
- **CSV writes:** one writer (`daily_delta.write_daily`) holding the key's lease, writing to a unique temp name (`f"{path}.{os.getpid()}.{uuid4().hex}.tmp"`) then `os.replace`; the fixed `path + ".tmp"` in `data_store.py` and `data_refresh._merge_save` is gone. File format unchanged, so a file rewritten with a flag on stays valid with it off.
- **Spot metals** (`XAUUSD`/`XAGUSD`) are never cached or written under their own name; their quotes keep `spot_metals`' own path and `SPOT_QUOTE_MAX_AGE_SECONDS`.
- **Yfinance stays serialised** (`yf_safe._DOWNLOAD_LOCK`) and cold fetches stay in processes; `tests/scanning/test_no_cross_ticker_mixing.py` stays green.
- **D5 rebuild:** price order trade < 60 s, then IEX bid/ask midpoint < 60 s, then a yfinance 1-minute bar whose own timestamp is < 60 s, else keep the scan price flagged `price_confirmed=False` ("price not confirmed live"). The IEX-stale feed for the 5 s re-quote is therefore: IEX quote midpoint, then yfinance 1-minute bar. Only `current_price` changes; the same frame, ATR and level inputs are reused; the quote is never spliced into the forming bar. Re-run gates: R:R, min/max stop distance, min reward (via `levels.build_scenarios`), horizon-noise floor (`atr_floor_pct`, `min_stop_distance_pct`), v115 stop clamp and the 2 % cap band (`build_confluence_plan`, `plan_stop_ceiling`, `planned_loss_pct`), `risk_sizing_ok`. Stateful gates are not re-run; a dropped plan consumes no cooldown and no dedup. Lanes: main scan (regular, pre- and after-market) and SHORT; **not** strategy alerts, **not** outlook. The embed, chart and persisted record all come from the rebuilt plan; posted plans are never altered.
- **5 s clock:** starts when the symbol's quote fetch completes, ends when the plan is persisted. A miss re-quotes once; a second miss posts with its true age and counts as a miss.
- **Record fields (D2), additive, `doc` JSONB, no migration, no read-time upcasting:** `TradePlanV2` gains `quote_at: str | None`, `quote_kind: str | None` (`"trade"`/`"mid"`/`"yf-1m"`/`"scan"`), `quote_age_s: float | None` (fetch completed to persisted), `quote_session: str | None` (`"regular"`/`"pre-market"`/`"after-hours"`/`"closed"`), `price_confirmed: bool | None`. Trade records gain `quote: dict | None` with keys `at`, `kind`, `age_s`, `session`, `confirmed`. Plan-manager exit events gain the same `quote` dict. Pre-v171 rows carry nothing and readers show `n/a`.
- **Tape (D7):** fixed tape `^GSPC ^NDX ^DJI ^VIX` plus any symbol an admin tab asked for in the last 15 minutes (the admin records demand into the shared cache, kind `INDEX_QUOTE`, key `tape-demand`). Proxies (`TAPE_PROXY_SYMBOLS`, default `^GSPC=SPY,^NDX=QQQ,^DJI=DIA,^VIX=VIXY,SI=F=SLV`) show change % only, never a level, labelled as a proxy. Yahoo-only entries with no proxy: any user-flagged non-index symbol other than `SI=F` keeps today's direct path (named in V171-28). A blank reply never overwrites the last good value; every value shows its age.
- **Admin freshness (D2 amendment):** the SPA marks requests made by a full page load (until the first in-app navigation) and by explicit refresh clicks with header `X-Swingbot-Fresh: 1`; the server then uses max age 0 for that request's layer calls, still single-flighted and at tier 5. In-app navigation is unmarked and reuses the shared cache. No new spinners, veils or blank states; the only new visible elements are the age hint (`12 s ago` / `1 min ago`, shown only when a price is older than its page's window), the proxy label and "price not confirmed live", each checked at 390, 768 and 1440 px (`docs/claude/ui-design.md`).

## Review Focus

1. **Postgres hung, not down** (a lock wait or slow disk): the 250 ms statement timeout fires and the stop monitor still gets its quote by fetching directly inside its own deadline; no loop stalls. Pinned in V171-6 (`test_hung_cache_read_fails_open_within_timeout`) and V171-10.
2. **A lease holder dies mid-fetch** (worker SIGKILLed by `_run_bounded`): a tier-1 waiter fetches for itself at its deadline, a tier-5 waiter gets the last cached value with its age, and the expired lease is taken by the next asker. Pinned in V171-6.
3. **Admin with an empty cache while the budget is short:** the page shows what a failed fetch shows today (`—`), never a spinner or veil, and the tape keeps its last good value with its age. Pinned in V171-25 and V171-29.
4. **Spot metals in a quote batch or the daily crawl:** `XAUUSD` never gets a cache key, sidecar or write-back of its own; its quote takes the spot path. Pinned in V171-9 and V171-12.
5. **A pre-market alert whose last IEX trade is yesterday's close and whose quote is older than 60 s:** the plan keeps the scan price, is flagged "price not confirmed live" with the session label `pre-market`, and still posts. Pinned in V171-18 and V171-22.
