## Goal

V209-12b replayed the built detector over the frozen 2026-11-05 session and it
stayed NORMAL all day, although the day was a real shock (SPY −4.4 % by the
close, VIX +27 %, the median watchlist name beyond −1 ATR from 15:45 UTC). The
code matched the spec; the entry rules did not fit the shape of that day. The
depth path counts equal-weight sectors (5 of 8 needed, the day never passed 4,
because 30 of 87 names sit in one sector), and the speed path needs a
+0.10 breadth jump twice running, which a grinding selloff never prints.

Amendment A1 re-registers the entry rule before any run on fresh days:
a **weighted depth** path (`depth_frac`, the share of contributing names sitting in
down sectors, with `breadth ≥ 0.40`) and a **sustained-breadth** path
(`breadth ≥ 0.50`, no speed needed) replace the sector-count path; the fast
path, VIX relief, open-settle, two-reading, exit, recovery, re-entry and carry
rules stay exactly as built. `SHOCK_SECTORS_FRAC` disappears from every site;
`SHOCK_DEPTH_FRAC` and `SHOCK_BREADTH_MAJORITY` (both 0.50, frozen) arrive.

Because the new bars were chosen after reading 2026-11-05, that day becomes an
in-sample fit check only. The evidence is a **validation set picked from daily
SPY, QQQ and ^VIX alone** over 2023-01-02..2025-12-31: 6 shock days, 12 calm
days, 4 tech-led rotation days, 4 hard-negative selloffs. The day list is
generated by code, committed, and frozen before a single detector run; one
gzip fixture per day is fetched from Alpaca and committed under
`tests/fixtures/shock_replay/`, so CI replays every day.

Success is a single acceptance run: SHOCK on ≥ 5 of 6 shock days, on ≤ 1 day
in each negative class, never earlier than 30 minutes after the open; lead
time, dwell, grind/flush mix and clustering are printed, never gated. A day
that cannot be built or reads `insufficient` counts against its class. **On a
fail, v209 closes `no-lift/`** (v210 with it; v211 is the partner's separate
call) with no tuning round. This plan touches no trade, no table shape, no
frontend and nothing Track 2 owns.

## Architecture

- `swingbot/core/market/shock.py` (pure): `ShockReading.depth_frac` (required,
  placed right after `sectors_total`), computed by `_sectors` from the same
  ≥ 2-member sector grouping; `entry_condition` ORs three paths
  (`_depth_path`, `_majority_path`, `_fast_path`); `_sectors_needed` deleted.
- Config: `SHOCK_SECTORS_FRAC` replaced in place by `SHOCK_DEPTH_FRAC` and
  `SHOCK_BREADTH_MAJORITY`; `shock_scan.THRESHOLD_ATTRS` follows. The reading's
  `doc` JSONB carries `depth_frac`; no Alembic revision (v209 is undeployed,
  the tables must be empty, checked in V209-A1-1 and again in V209-13).
- `scripts/data/shock_validation_days.py` (new, pure + CLI): daily CSVs → the
  frozen day list `tests/fixtures/shock_replay/validation_days.json`.
- `scripts/data/build_shock_replay_fixture.py` (v209 branch): a session date,
  DST-aware bounds from `session.US_MARKET_TZ` / `RTH_OPEN` /
  `session.session_close`, a daily-^VIX path, per-(day, ticker) raw cache,
  a validation mode writing one `<date>.json.gz` per day, never synthetic.
- `tests/market/test_shock_acceptance_a1.py` (renamed from the V209-12b test):
  replays every frozen day from a fresh `ShockState()`, scores, reports.

**Tech stack:** Python 3.11, pandas, gzip/json stdlib, pytest; Alpaca history
fetcher (`scripts/data/alpaca_history/`).

## Global Constraints

- **Frozen values (spec A1):** `SHOCK_DEPTH_FRAC = 0.50`, `SHOCK_BREADTH_MAJORITY = 0.50`; VIX relief (−0.05 at VIX change ≥ +15 %) applies to the breadth bar of both new paths, never to the depth bar. No other threshold changes. **v209 config has 20 fields after A1** (mode + 18 thresholds + `SHOCK_READINGS_KEEP_DAYS`).
- **`depth_frac`** = (contributing names in down sectors) / (contributing names in sectors with ≥ 2 contributing members); a sector is down when its median ATR move ≤ −`atr_k`; `None` when no sector has ≥ 2 contributing members. Names with no sector count toward breadth only. `sectors_down`/`sectors_total` stay in the reading, display only.
- **Entry from NORMAL:** `_depth_path` = `depth_frac ≥ depth_frac_bar` and `breadth ≥ breadth_enter − relief`; `_majority_path` = `breadth ≥ breadth_majority − relief`; `_fast_path` unchanged; the two-consecutive, open-settle and every non-NORMAL rule unchanged.
- **No upcasting:** `ShockReading.from_row` keeps raising on a missing `depth_frac`. Before V209-A1-1 lands, the local replica and production must hold **no** `market_shock_readings` rows (production: table absent or empty); local rows are dropped.
- **Validation window 2023-01-02..2025-12-31**, daily SPY/QQQ from `data/market_data_pit/daily/{SPY,QQQ}.csv` and ^VIX from `market_data/vix/VIX_daily.csv`, read from the **main repo path** (the worktree has no data dirs). Returns are close-to-close in % from rows before the window too (the first window day has its prior close). A date missing from any of the three series is not selectable.
- **Selection rules, verbatim from the spec, applied in this order with each class skipping days an earlier class took:** shock (6 largest SPY drops, skipping any day within 5 sessions of a chosen one; session distance = index distance in the SPY calendar) (only `spy_ret < 0`) → hard (4 largest SPY drops in [−2.5 %, −1.5 %] with VIX change < +15 %) → rotation (4 most negative `QQQ − SPY` among SPY ≥ −1.5 % and VIX change < +15 %) → calm (|SPY| < 0.5 % and VIX change < +3 %; date-sorted, shuffled with `random.Random(209)`, taken in order skipping a year that already holds 4, until 12).
- **The day list is committed before any validation fixture is fetched and before any detector run on a validation day;** the selector refuses to overwrite it.
- **No synthetic data for validation days.** A day whose fetch fails or has fewer than `ShockThresholds().min_names` equities is written as a `source: "unbuildable"` fixture and scored as a miss (shock) or a false fire (negatives). Missing Alpaca keys abort the run with no fixture written (an operator error, not a data answer).
- **No lookahead in fixtures:** `last` = close of the last 15-minute bar finished by the step; daily bars end the day before the session (`fetch_raw(..., end=datetime(day, 00:00 UTC))`).
- **Acceptance is one shot** (spec § Acceptance): recall ≥ 5/6; SHOCK on ≤ 1/12 calm, ≤ 1/4 rotation, ≤ 1/4 hard; first SHOCK never before open + 30 min. 2026-11-05 is reported, never gated. A red acceptance test is a measured answer: stop, report, never tune, refetch or regenerate.
- Every function written or changed < 15 cyclomatic complexity; narrow runs only (`python scripts/dev/testrun.py file <test>`); no task runs the full suite; tests stay in existing suites (`tests/market/`, `tests/scanning/`, `tests/scripts/`, `tests/db/`, `tests/`); commits on the v209 branch, one subject line, no trailers.

## Review Focus

1. **Half-day and DST sessions in the validation set.** A calm day after Thanksgiving closes 13:00 ET; a March/November day flips between 13:30 and 14:30 UTC opens. Owner: V209-A1-2b (`session_bounds` tests for EDT, EST and an early close).
2. **Overlapping classes.** A −2.4 % day could qualify as a shock day and a hard negative. Owner: V209-A1-2 (precedence test).
3. **A partial fetch.** A day where the run died after 40 of 89 tickers must resume from the per-(day, ticker) cache, never write a fixture from 40 names. Owner: V209-A1-2b (resume test; a day fixture is written only after every ticker is attempted).
4. **Insufficient mid-day readings.** One thin reading on a shock day counts it as a miss. Owner: V209-A1-4 (scoring unit test).
5. **Stale `sectors_frac` in a local `.env`.** An operator `.env` still holding `SHOCK_SECTORS_FRAC` must not break config load. Owner: V209-A1-1 (unknown key ignored, pinned).
