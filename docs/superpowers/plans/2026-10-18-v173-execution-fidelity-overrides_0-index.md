**Goal:**

The bot trades its own plans mechanically; the one place a human changes an outcome is the admin **close** verb (`trade_commands.py:_close_plan`). Production on 2026-10-17 held 563 CLOSED plans, 36 of them closed `manual`: about 21 individual overrides between 2026-08-14 and 2026-09-22, plus 15 from a single bulk clear on 2026-09-30 20:54–20:55 UTC. Nobody can say whether those overrides helped, for two reasons: a manual close stores no exit price (only `{status, reason, at}`), and a bulk clear is recorded exactly like a decision. Douglas's point, that a trader who takes profit early or moves stops is trading an unmeasured system, has never been checked against this book.

Once this ships, every manual close stamps its exit price, the price's source, the quote time and the bar-cache date onto its `CLOSED` transition, and a bulk clear says `manual_bulk`. The 15 historical bulk closes are re-tagged by a pinned-id Alembic data revision. A pure replay module re-runs each overridden plan through the v2 exit engine from its real fill bar (never resuming mid-trade), books both arms through the same `costs.book` call shape, and reports per override the R and dollars the engine would have realised had the plan been left alone. A report script (run on the VM), `GET /api/v1/analytics/override-fidelity` and an "Overrides vs engine" panel on the Analytics Execution tab show the rows, the descriptive totals and a verdict badge.

It leaves alone how a manual close settles (`legs_realized`, `r_multiple`, equity, every existing analytics figure), every signal, gate, stop, size and badge, and the live plan lifecycle: no ghost plans, no `resume` in `exit_sim_v2`, no eToro code, no Discord verb.

Success is measured by integrity, not lift: every new manual close carries a four-field `override` stamp; the 15 pinned rows read `manual_bulk` on production; the report runs on the VM over the real book and prints every override with exactly one status; and the verdict stays `WAITING` until its frozen floors (30 stamped individual resolved rows over 10 ISO weeks, none open, exclusions ≤ 20%) hold, after which it is evaluated once, written to `preregistration-ledger.jsonl` as `v173-override-fidelity` and never recomputed.

**Architecture:** Stamping lives in `swingbot/admin/api_v1/trade_commands.py` (a never-raising `_override_stamp` helper, `record_transition(..., extra=)` from `plan_types.py`). Replay and descriptive rows live in the new pure module `swingbot/core/analytics/override_fidelity.py`, which adapts a live plan to `walk_v2` through a new public `exit_sim_v2.fill_bar_exit` and the additive `ExitResult.tp1_index`. The frozen verdict, its ledger row and the I/O-free `build_report` live in the new `swingbot/core/analytics/override_verdict.py`; the report script and the API route only load inputs (plans, linked trades, `runner_path.cached_daily_bars`, the ledger) and call it. The SPA gets a store slice on `AnalyticsStore` and a standalone `sb-override-fidelity-panel` mounted in `execution.ts`.

**Tech Stack:** Python 3.11, pandas, numpy, Flask blueprint `api_v1`, Alembic (data revision over `plans.doc` JSONB), Angular (signals, `@ngrx/signals` store, zoneless), Vitest via `ng test`, Playwright for the three-width check.

## Global Constraints

- **No behaviour change to settling a close.** `legs_realized`, `r_multiple`, equity, the linked trade's settlement and every existing analytics figure are untouched. The stamp is extra fields on the transition entry, read only by this report. Signals, gates, stops, sizes and badges are untouched.
- **`record_transition(plan, new_status, reason=None, at=None, extra: dict | None = None)`**: `extra` is merged into the appended entry (`{"status", "reason", "at", **extra}`); with `extra=None` the entry is exactly `{"status", "reason", "at"}` as today. No other caller changes.
- **`_close_plan(store, plan, reason: str = "manual") -> None`**: `close_trade` calls `_close_plan(store, plan)` (default `"manual"`); `close_open` calls `_close_plan(store, plan, "manual_bulk")` **positionally** (the existing test monkeypatches `_close_plan` with a two-argument `flaky(store, plan)`; V173-3 updates that stub to `flaky(store, plan, reason="manual")`).
- **The `override` stamp** (key on the CLOSED transition entry): `{"exit_price": float | None, "price_source": "quote" | "bar_close" | "none", "quote_ts": str | None, "bars_asof": str | None}`. The quote comes from `swingbot.core.marketdata.data.get_current_price_detail(ticker, allow_stale=False)` looked up through the module at call time (tests monkeypatch it there), fetched **once**, `quote_ts = datetime.now(timezone.utc).isoformat()` at fetch. No quote → `exit_price` = last `Close` of `rp.cached_daily_bars(ticker)`, `price_source="bar_close"`, `quote_ts=None`. Neither → `exit_price=None`, `price_source="none"`. `bars_asof` = ISO date of that cache's last bar, or `None`. Building it **never raises**: any exception logs a warning and the entry gets `"override": None`; the close goes ahead.
- **One price for stamp and trade:** `TradeLog.close_trade_manual(trade_id, reason="manual", *, exit_price: float | None = None)` uses `exit_price` when given and skips its own fetch; `None` keeps today's fetch. `_close_plan` builds the stamp first and passes `exit_price=stamp["exit_price"]` only when `price_source == "quote"`.
- **`manual_bulk` readers:** `partials._REASON_BUCKET["manual_bulk"] = "manual"`; frontend `EXIT_REASON_LABELS` gains `manual_bulk: 'Bulk close'`. `export_book_rows.sh`, `trades.py`, `lifecycle_embeds.py`, `session_expiry.cancel_reason` stay unchanged.
- **Data revision** `revision = "v173_001"`, file `swingbot/core/db/migrations/versions/v173_001_manual_bulk_retag.py`, `down_revision` = the current head at implementation time (`python -m alembic heads`; `v146_001` when this plan was written, `v172_001` if v172 merged first). `PINNED_PLAN_IDS: tuple[str, ...]` holds exactly the 15 ids from § Pinned bulk-clear ids. Upgrade is a logged no-op when **none** of the pinned ids exist (every non-production database: tests, CI, fresh installs); it refuses (raises `RuntimeError`, nothing written) if only some exist, or any present one's last `status_history` entry is not `{"status": "CLOSED", "reason": "manual"}`; V173-18's post-deploy check that exactly 15 rows read `manual_bulk` catches a production no-op. Otherwise it sets that entry's `reason` to `"manual_bulk"`. Downgrade refuses unless every pinned last entry reads `manual_bulk`, then sets it back to `"manual"`. The pure helpers `retag(histories: dict[str, list], *, frm: str, to: str) -> dict[str, list]` (raises `RuntimeError` on a missing id or a mismatch) carry the logic; `upgrade()`/`downgrade()` only read `plan_id, doc->'status_history'` for the pinned ids and write `jsonb_set(doc, '{status_history}', CAST(:hist AS jsonb))` per id.
- **Exit engine hooks (additive, behaviour-preserving):** `ExitResult.tp1_index: int | None = None` (last field, after `cancel_reason`), set by `walk_v2` to the TP1 bar index on both TP1 paths (full exit at TP1, and scale-out runner) and `None` everywhere else, v1 included. `exit_sim_v2.fill_bar_exit(df, j: int, fill: float, plan, instrument) -> ExitResult | None` is the public name of `_fill_bar_v2` (the private name stays as an alias so `_filled` is unchanged). Every existing exit test stays green unchanged.
- **Module `swingbot/core/analytics/override_fidelity.py`** is pure: no store, no network, no file reads. Bars come in as a DataFrame (`Open/High/Low/Close/Volume`, DatetimeIndex). Instrument `contract.resolve("v2")`; hold cap `exit_sim._hold_cap_bars(plan, HORIZONS[plan.horizon_key]["max_holding_days"])`; `scale_out = plan.tp1_fraction < 1.0`; engine flags `config.STALL_EXIT_ENABLED` and `config.RUNNER_STRUCTURE_EXIT` read live and echoed in the report.
- **Override set:** CLOSED plans whose **last** `status_history` entry has `reason` in `MANUAL_REASONS = ("manual", "manual_bulk")`. `bulk = reason == "manual_bulk"`. `source = "manual"` on every row (stage B adds `"etoro_demo"`; no stage B code here).
- **Session assignment** `assign_session(at_iso) -> SessionHit(session: date, price_kind: "open" | "close") | None`, on `nyse_calendar()` in America/New_York: a session day before 09:30 → that day, `"open"`; from 09:30 on (regular hours or after `session_close(d)`, early closes included) → that day, `"close"`; a non-session day → the last session on or before it, `"close"`. Unparseable → `None`. The fill session is `assign_session(<ACTIVE entry at>).session`; the override session is `assign_session(<CLOSED entry at>).session`; the live TP1 session is `assign_session(<PARTIAL entry at>).session`.
- **Actual exit price:** the stamp's `exit_price` when not `None` (`price_source` `"quote"` or `"bar_close"`, `approx=False`); otherwise the override session bar's `Open` (`price_kind == "open"`, `price_source="session_open"`) or `Close` (`"session_close"`), `approx=True`. A missing `override` key is unstamped, never inferred (schema-evolution: no read-time upcasting).
- **Replay, two frames, no lookahead:** both start at `fill_idx` with `entry_price = plan.entry_price` and `plan.stop_loss` (the original stop): first `fill_bar_exit`, then `walk_v2`. The **real frame** is the cached bars; it decides parity and ambiguity. The **engine frame** is the same bars with the override session's `High`/`Low` replaced by `max(Open, Close)`/`min(Open, Close)`; its result is the engine arm (`engine_r`, `engine_exit_reason`). Bars before the fill never change `engine_r`; changing the override session's high/low never changes a `resolved` row's `engine_r`.
- **Status precedence** (first match wins): `unreplayable` (no ACTIVE entry, no/empty bars, fill session not in the bars, `plan.entry_price` or `stop_loss` missing, no actual exit price, or `costs.book` raises) → `stale` (`bars.index[-1].date() < asof`) → `split_affected` (`plan.entry_price` outside `[Low × 0.98, High × 1.02]` of the fill-session bar) → `parity_mismatch` (real-frame exit index `< ov_idx`; or ACTIVE at close and real-frame `tp1_index < ov_idx`; or PARTIAL at close and real-frame `tp1_index != ` the live TP1 session's index) → `ambiguous` (real-frame `tp1_index == ov_idx` for an ACTIVE plan, or real-frame exit on `ov_idx` through a leg of kind `stop` or `target`) → `open` (engine-frame last leg reason in `TIMEOUT_REASONS`, exit index `== len(df) - 1` and `fill_idx + hold_cap_bars > len(df) - 1`) → `resolved`.
- **One cost basis:** each arm is one `costs.book(resolve("v2").cost_model, direction=plan.direction, entry_price=plan.entry_price, stop_loss=plan.stop_loss, legs=[...])` call. PARTIAL plans: both arms carry the live TP1 leg `{"fraction": plan.tp1_fraction, "exit_price": <legs_realized leg with reason "tp1">["exit_price"], "reason": "tp1", "kind": "target"}`. Actual arm adds `{"fraction": 1 - tp1_fraction (PARTIAL) or 1.0 (ACTIVE), "exit_price": actual, "reason": "manual", "kind": "stop"}`. Engine arm adds the engine-frame result's legs except its `tp1` leg on a PARTIAL plan, each with `kind = leg_kind(reason)` (`"target"` for `tp1`/`runner_tp2`; `"close"` for `timeout`, `runner_timeout`, `acceptance_exit`, `stall_exit`, `runner_progress_stall`, `exit_sim.TIME_EXIT_REASON`; `"stop"` for every other reason), fractions re-scaled so the remainder legs sum to the remainder fraction. `delta_r = actual_r - engine_r`, rounded to 3 dp.
- **Dollars:** `dollar_risk = float(trade["shares"]) * abs(plan.entry_price - plan.stop_loss)` from the linked trade (`TradeLog` record for the plan id); no trade or no `shares` → `None`, and every `*_usd` is `None` (shown "—") while the row stays in the R sums. `*_usd = round(r * dollar_risk, 2)`. Figures are net of modelled costs and pre-tax.
- **Frozen constants** (changing any is a new spec): `DEAD_BAND = 0.05` (helped `> +0.05`, hurt `< -0.05`, else neutral), `VERDICT_FLOOR = 30`, `WEEK_FLOOR = 10`, `EXCLUDED_CAP = 0.20`, `SPLIT_TOLERANCE = 0.02`, `LEDGER_ID = "v173-override-fidelity"`.
- **Counted rows** (tiles, ΣΔ, helped/hurt/neutral, splits, verdict population): `not bulk and not approx and status == "resolved"`. Bulk rows and approx rows are shown in the table, never summed; they produce the exclusion notes.
- **Verdict:** eligible = `not bulk and not approx`. Evaluable iff counted `n >= 30`, distinct ISO weeks of their `close_date >= 10`, no eligible row `open`, and eligible rows with an excluded status (`stale`, `ambiguous`, `parity_mismatch`, `split_affected`, `unreplayable`) `<= 20%` of eligible rows. Evaluation: `stats.week_cluster_bootstrap(rows, (), mean-ΔR statistic)` with `stats.WEEK_BOOTSTRAP_RESAMPLES`/`stats.WEEK_BOOTSTRAP_SEED`, 95% percentile interval (`np.percentile(draws, [2.5, 97.5])`); `hi < 0` → `COST`, `lo > 0` → `SAVED`, else `INCONCLUSIVE`. `stats.VERDICTS` gains `"COST", "SAVED", "INCONCLUSIVE"`; `WAITING` is never written. The ledger row (`instrument "v2"`, `n`, `exp_r` = mean ΔR, `p` null, `record` = the spec path) is appended **once**, only by the report script run with `--production`; a recorded row is always returned as is, never recomputed. The API never evaluates.
- **Report payload** (API body, script `--json`): keys exactly `rows, summary, verdict, engine_flags, asof, currency_symbol`. Row keys exactly `plan_id, ticker, horizon, direction, state_at_close, close_date, bulk, approx, price_source, status, actual_r, engine_r, delta_r, actual_usd, engine_usd, delta_usd, engine_exit_reason, outcome, source`. Summary keys exactly `n_by_status, bulk_n, bulk_dates, approx_n, counted_n, sum_delta_r, sum_delta_usd, usd_missing_n, helped, hurt, neutral, splits` (`splits` = `{"state_at_close"|"horizon"|"direction": {<value>: {"n", "sum_delta_r", "sum_delta_usd"}}}`). Verdict keys exactly `state, n, needed, weeks, week_floor, open_n, excluded_share, evaluable, recorded, recorded_on, mean_delta_r, ci`.
- **Bars** come only from `swingbot.core.analytics.runner_path.cached_daily_bars` (`market_data/daily`), never fetched. `asof` = `latest_completed_session(now)`: the last NYSE session whose `session_close` is at or before `now`.
- **Report script** `scripts/reports/execution_fidelity_report.py`: without `--production` it prints the banner `DEV DATABASE: fixture data, not the real book. The ledger is never written.` first and never writes the ledger; `--production` is passed only on the VM. On an evaluating run it appends the ledger row and prints it as one JSON line for mirroring into the repo.
- **UI copy (verbatim):** panel title `Overrides vs engine`; tile order net effect (`±$X · ±Y R`), `Overrides counted`, `Helped / hurt / neutral` with hint `counts ignore size`, verdict badge. Badge: WAITING `N of 30 needed. No conclusion yet.`; COST `Your overrides cost $X (Y R) vs the engine`; SAVED `Your overrides saved $X (Y R) vs the engine`; INCONCLUSIVE `No clear difference vs the engine` ($X = |summary.sum_delta_usd|, Y = |summary.sum_delta_r|). Caption: `Compares the overrides you made with what the engine would have done. Past closes only, not advice on future ones. There is no target number of overrides.` Exclusion notes, one per non-zero count: `<n> closes from one bulk clear on <date> are not decisions, so they are left out` (one line per bulk date), `<n> estimated rows are shown but not counted`, and `<n> <status label> rows are left out` per excluded status.
